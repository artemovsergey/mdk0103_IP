# Лекция 23. Нативные возможности и сборка приложения

Смартфон умеет гораздо больше, чем показывать текст и кнопки: у него есть камера, микрофон, спутниковый приёмник, датчики движения. Доступ приложения к этим устройствам называют **нативными возможностями**. React Native выполняется на JavaScript, и сам по себе он не умеет общаться с камерой или приёмником — для этого нужны **нативные модули**, написанные под конкретную платформу. Expo предоставляет готовые модули, которые подключаются одной командой.

На этом занятии вы познакомитесь с нативными возможностями Expo, научитесь запрашивать разрешения у пользователя и узнаете, как приложение превращается из учебного проекта в готовый файл для установки.

### Что вы узнаете

- Как Expo открывает доступ к камере, геолокации и файлам.

## Что такое нативные возможности

Интерфейс приложения вы описываете на TypeScript, но все «сложные» действия выполняет операционная система телефона: делает снимок, определяет координаты, сохраняет файл. Приложению остаётся попросить систему выполнить нужную операцию и обработать результат.

Примеры нативных возможностей:

- камера и галерея;
- геолокация;
- файловая система устройства;
- уведомления;
- датчики движения, освещённости, шагомер;
- буфер обмена, контакты, сканер отпечатка.

Всё это — возможности самого устройства. Чтобы приложение получило к ним доступ, в проект подключают нативные модули.

## Как Expo даёт доступ к возможностям устройства

**Expo SDK** — это набор готовых модулей для самых разных возможностей телефона. Каждый модуль — отдельный пакет, который устанавливается в проект:

| Модуль | Возможность |
|:--|:--|
| `expo-image-picker` | Камера и галерея |
| `expo-location` | Геолокация |
| `expo-file-system` | Файлы на устройстве |
| `expo-notifications` | Уведомления |
| `expo-sensors` | Датчики устройства |
| `expo-clipboard` | Буфер обмена |

Модули устанавливают командой `npx expo install`:

```bash
npx expo install expo-image-picker
```

Почему не `npm install`? Команда `npx expo install` подбирает версию пакета, совместимую с версией Expo SDK в проекте. Если поставить модуль обычным `npm install`, версия может не подойти, и приложение перестанет запускаться.

## Разрешения

Доступ к камере, микрофону, геолокации и файлам — это доступ к личным данным, поэтому операционная система требует согласия пользователя. Если приложение обратится к камере без разрешения, система его заблокирует.

Разрешения работают на двух уровнях.

1. **Запрос во время работы.** Модуль вызывает метод вида `request...PermissionsAsync()`, и на экране появляется системный диалог «Разрешить доступ?». Результат запроса — объект с полем `granted`: `true`, если пользователь согласился.
2. **Декларация в настройках приложения.** В файле `app.json` описано, к чему приложение запрашивает доступ. Тексты запросов и нужные системные разрешения добавляют **конфиг-плагины** Expo — инструкции для сборщика приложений. Они выполняются автоматически, писать нативный код руками не нужно.

Правило: сначала запрашивайте разрешение, и только затем выполняйте действие. Если пользователь отказал — покажите понятное сообщение, а не «молчаливую» ошибку.

## Камера и галерея: expo-image-picker

Модуль `expo-image-picker` показывает системную камеру или галерею и возвращает ссылку на выбранное изображение. Установите его:

```bash
npx expo install expo-image-picker
```

Сначала запрашиваем разрешение на камеру с помощью `requestCameraPermissionsAsync()`, затем открываем камеру методом `launchCameraAsync()`:

```tsx
import * as ImagePicker from 'expo-image-picker'

async function takePhoto() {
  const permission = await ImagePicker.requestCameraPermissionsAsync()

  if (!permission.granted) {
    return
  }

  const result = await ImagePicker.launchCameraAsync({
    mediaTypes: ['images'],
    allowsEditing: true,
    quality: 0.7,
  })

  if (result.canceled) {
    return
  }

  const photoUri = result.assets[0].uri
  console.log(photoUri)
}
```

Выбор изображения из галереи устроен так же, только разрешение запрашивает `requestMediaLibraryPermissionsAsync()`, а окно галереи открывает `launchImageLibraryAsync()`:

```tsx
const permission = await ImagePicker.requestMediaLibraryPermissionsAsync()
const result = await ImagePicker.launchImageLibraryAsync({ mediaTypes: ['images'] })
```

Разберём основные параметры и результат:

- `mediaTypes: ['images']` — показывать только изображения (не видео).
- `allowsEditing: true` — после съёмки пользователь может кадрировать снимок.
- `quality` — качество изображения от `0` до `1`; меньшие значения уменьшают размер файла.
- `result.canceled` — `true`, если пользователь закрыл камеру или галерею, ничего не выбрав.
- `result.assets` — список выбранных файлов; у первого из них поле `uri` содержит ссылку на изображение.

Ссылку `uri` передают компоненту `Image` или сохраняют, чтобы показать снимок позже.

> Примечание: камера доступна только на реальном устройстве. В браузере работают только выбор файла и галерея, поэтому камеру проверяйте на телефоне в Expo Go.

## Геолокация: expo-location

Модуль `expo-location` определяет координаты устройства:

```bash
npx expo install expo-location
```

Разрешение запрашивается отдельно для работы приложения на экране (`requestForegroundPermissionsAsync`) и в фоне (`requestBackgroundPermissionsAsync`). Для учебных задач достаточно первого. После разрешения координаты получают методом `getCurrentPositionAsync`:

```tsx
import * as Location from 'expo-location'

async function showPosition() {
  const permission = await Location.requestForegroundPermissionsAsync()

  if (!permission.granted) {
    return null
  }

  const position = await Location.getCurrentPositionAsync({})
  return position.coords
}
```

Объект `coords` содержит поля `latitude` (широта), `longitude` (долгота) и `accuracy` (точность в метрах). Если приложению нужно следить за перемещением, используют подписку `watchPositionAsync`, которая вызывает обработчик при каждом изменении координат.

Конфиг-плагин модуля сам добавляет в приложение тексты разрешений: пользователь видит, зачем приложению нужна геолокация.

## Работа с файлами: expo-file-system

Модуль `expo-file-system` даёт доступ к файлам на устройстве:

```bash
npx expo install expo-file-system
```

У приложения есть две основные папки:

- `documentDirectory` — постоянные файлы приложения; сохраняются между запусками, пока пользователь не удалит приложение.
- `cacheDirectory` — временные файлы; система может очистить их в любой момент.

Модуль умеет:

- читать и записывать текстовые файлы;
- скачивать файл по ссылке;
- копировать, перемещать и удалять файлы;
- сообщать размер, дату и существование файла.

Файлы нужны, когда данные не помещаются в хранилище «ключ — значение»: например, чтобы сохранить сделанные снимки, выгрузить отчёт или работать с документами без интернета.

> Замечание: в новых версиях Expo SDK у модуля появился объектный интерфейс с классами `File` и `Directory`, а прежние функции доступны через путь `expo-file-system/legacy`. В рамках курса достаточно знать, какие задачи решает модуль.

## Зачем нужен development build

**Expo Go** — учебное приложение, внутри которого уже собраны популярные модули Expo. Пока проект использует только их, приложение запускается в Expo Go без сборки: QR-код, и всё работает.

Но возможности Expo Go ограничены. Собственная сборка нужна, если:

- в проекте есть модуль, которого нет в Expo Go;
- вы добавили конфиг-плагин, меняющий настройки приложения;
- нужно проверить, как приложение ведёт себя в «настоящем» виде, без ограничений Expo Go.

Такую сборку называют **development build**: это полноценное приложение с вашим набором модулей, установленное на телефон и подключённое к серверу разработки. Создаётся она через EAS Build.

## Обзор EAS Build

**EAS** (Expo Application Services) — облачные сервисы Expo. Их три:

- **Build** — собирает приложение;
- **Submit** — отправляет готовое приложение в магазины;
- **Update** — доставляет обновления JavaScript без пересборки.

EAS Build работает в облаке: проект архивируется и отправляется на серверы Expo, где собирается готовый файл — APK для Android, AAB для магазина или IPA для iOS. На выходе вы получаете ссылку, по которой файл можно скачать.

Основные команды:

```bash
npx eas-cli@latest login
npx eas-cli@latest build:configure
npx eas-cli@latest build -p android --profile preview
```

- `login` — вход в аккаунт Expo.
- `build:configure` — подготовка проекта: создаётся файл настроек сборки `eas.json`.
- `build` — запуск сборки; `-p android` выбирает платформу, `--profile preview` — профиль сборки.

В `eas.json` описаны профили:

- `development` — development build для разработки;
- `preview` — сборка для тестирования на телефоне;
- `production` — сборка для публикации в магазинах.

> Сборка в облаке занимает время: обычно от 10 до 30 минут, а на бесплатном тарифе возможна очередь. Для работы нужен бесплатный аккаунт Expo на сайте expo.dev.

Подробнее сборку и публикацию мы разберём в практической работе 30.

## Резюме

- Нативные возможности — это доступ приложения к камере, геолокации, файлам и другим устройствам телефона.
- Expo SDK даёт готовые модули; их устанавливают командой `npx expo install`, чтобы версии совпадали с SDK.
- Перед доступом к личным данным приложение обязано получить разрешение пользователя.
- `expo-image-picker` открывает камеру и галерею и возвращает ссылку `uri` на изображение.
- `expo-location` определяет координаты устройства, `expo-file-system` работает с файлами.
- Expo Go подходит не для всех модулей — тогда создают development build.
- EAS Build собирает приложение в облаке по профилям из `eas.json`.
