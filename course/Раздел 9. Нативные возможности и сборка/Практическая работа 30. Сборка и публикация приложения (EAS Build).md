# Практическая работа 30. Сборка и публикация приложения (EAS Build)

До сих пор приложение работало внутри Expo Go. Чтобы получить самостоятельный файл, который можно установить на телефон и передать другому человеку, приложение нужно собрать. В этой работе вы соберёте Android-версию приложения `Juice Tracker` в облаке с помощью **EAS Build** — сервиса Expo. Сборка выполняется на серверах Expo, поэтому на компьютере не нужны дополнительные инструменты.

> Важно: для работы нужен бесплатный аккаунт Expo, а сборка занимает время — от 10 до 30 минут, на бесплатном тарифе возможна очередь. Планируйте работу заранее.

### Пререквизиты

### Что вы создадите

Готовый APK-файл приложения `Juice Tracker`. Вы установите его на телефон как обычное приложение — без Expo Go.

## Шаг 1. Аккаунт Expo

1. Откройте сайт expo.dev и нажмите **Sign up**.
2. Зарегистрируйтесь по электронной почте и подтвердите адрес.
3. Запомните логин и пароль — они понадобятся для входа в командной строке.

Бесплатного аккаунта достаточно: он позволяет собирать приложения, хранить ключи подписи и следить за сборками на сайте.

## Шаг 2. Вход в EAS CLI

EAS CLI — программа, которая отправляет проект на сборку. Отдельно устанавливать её не нужно: `npx` скачает актуальную версию при первом запуске. Выполните в папке проекта:

```bash
npx eas-cli@latest login
npx eas-cli@latest whoami
```

- `login` попросит электронную почту и пароль от аккаунта Expo.
- `whoami` должен вывести имя вашего аккаунта — это значит, что вход выполнен.

## Шаг 3. Настройка проекта

Подготовьте проект к сборке:

```bash
npx eas-cli@latest build:configure
```

Команда спросит платформу — выберите **Android**. В корне проекта появится файл `eas.json`, а проект будет связан с вашим аккаунтом Expo.

Если в файле `app.json` не указано имя пакета, EAS спросит его при первой сборке. Имя пакета — уникальный идентификатор приложения, например `com.student.juicetracker`. Его можно задать заранее:

```json
{
  "expo": {
    "name": "Juice Tracker",
    "slug": "juice-tracker",
    "version": "1.0.0",
    "android": {
      "package": "com.student.juicetracker"
    }
  }
}
```

Имя пакета состоит из латинских букв и точек. После публикации в магазине его изменить нельзя — выберите его один раз и обдуманно.

## Шаг 4. Файл eas.json

Файл `eas.json` описывает, как собирать приложение. Пример его содержимого:

```json
{
  "cli": {
    "version": ">= 12.0.0"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal",
      "android": {
        "buildType": "apk"
      }
    },
    "production": {
      "autoIncrement": true
    }
  },
  "submit": {
    "production": {}
  }
}
```

- `cli.version` — минимальная версия EAS CLI, которая подойдёт проекту.
- `build` — профили сборки, их можно дополнять и изменять.
- `submit` — настройки команды `eas submit` для публикации.

Профили:

| Профиль | Назначение | Результат |
|:--|:--|:--|
| `development` | Разработка с development build | Приложение с подключением к серверу разработки |
| `preview` | Тестирование на телефоне | APK-файл |
| `production` | Публикация в магазинах | AAB для Google Play, IPA для App Store |

В профиле `preview` строка `buildType: "apk"` гарантирует, что на выходе будет установочный APK, а не файл для магазина. `autoIncrement` в профиле `production` автоматически увеличивает номер версии при каждой сборке.

## Шаг 5. Первая сборка

Запустите сборку по профилю `preview`:

```bash
npx eas-cli@latest build -p android --profile preview
```

Что произойдёт:

1. EAS проверит настройки и спросит имя пакета, если оно не задано (например, `com.student.juicetracker`).
2. Предложит создать хранилище ключей (**Keystore**) — ответьте Yes: EAS создаст ключ подписи и сохранит его в вашем аккаунте.
3. Проект отправится архивом в облако, а в терминале появится ссылка на страницу сборки.

Дальше сборка идёт без вашего участия: статус на expo.dev меняется с **Queued** на **In progress**, а затем на **Finished**. Терминал можно закрыть — сборка продолжится в облаке.

## Шаг 6. Установка APK на телефон

1. Откройте ссылку на сборку со страницы expo.dev на телефоне (страница откроется и по QR-коду).
2. Скачайте APK-файл.
3. Разрешите установку из этого источника, когда система спросит.
4. Найдите приложение «Juice Tracker» в списке установленных и запустите его.

Это самостоятельная сборка: Expo Go ей не нужен, а записи дневника сохраняются в приложении между запусками.

## Шаг 7. Публикация в магазине (обзор)

Команда `eas submit` отправляет готовую сборку в магазин приложений:

```bash
npx eas-cli@latest submit -p android --profile production
```

Для публикации в Google Play понадобятся:

- production-сборка — `npx eas-cli@latest build -p android --profile production` (на выходе AAB);
- аккаунт разработчика Google Play;
- ключ доступа (service account), созданный в Google Play Console.

В рамках курса достаточно знать, что такая команда существует и что публикация требует аккаунтов магазинов.

## Возможные проблемы

- **Сборка долго в очереди.** На бесплатном тарифе сборки выполняются по очереди — подождите.
- **Сборка завершилась с ошибкой.** Откройте ссылку из терминала и изучите журнал на expo.dev; чаще всего причина — ошибка TypeScript или забытая зависимость.
- **APK не устанавливается.** Разрешите установку приложений из неизвестных источников и удалите ранее установленную копию.
- **`whoami` сообщает, что вы не вошли.** Выполните `npx eas-cli@latest login` заново.

## Проверьте работу

1. Команда `npx eas-cli@latest whoami` выводит имя вашего аккаунта.
2. В корне проекта есть файл `eas.json` с тремя профилями.
3. На странице сборки статус **Finished**, ссылка на APK доступна.
4. Установленный APK запускается на телефоне без Expo Go и сохраняет записи после закрытия.

## Резюме

- EAS Build собирает приложение в облаке — дополнительные инструменты на компьютере не нужны.
- Проект настраивается командой `build:configure`, профили сборки описаны в `eas.json`.
- Профиль `preview` с `buildType: "apk"` даёт установочный файл для тестирования на телефоне.
- Готовый APK скачивают со страницы сборки и устанавливают как обычное приложение.
- `eas submit` отправляет production-сборку в магазины приложений.
