# Лекция 13. Отладка приложения (Dice Roller)

Отладка — это процесс поиска и исправления ошибок в коде. На этом занятии вы научитесь использовать инструменты отладки приложений React Native (Expo), чтобы видеть, что происходит в приложении во время выполнения.

Будем работать с приложением **Dice Roller**: при нажатии на кнопку оно показывает случайное число от 1 до 6.

### Необходимые условия

- Приложение Dice Roller из практической работы.
- Знание компонентов `Text`, `View`, `Pressable` и хука `useState`.

### Что вы узнаете

- Как выводить сообщения в консоль с помощью `console.log`.
- Как просматривать консоль в Expo и в браузере.
- Как ставить точки останова в браузере и в VS Code.
- Как использовать оператор `debugger`.
- Как исследовать приложение с помощью React DevTools.

## Приложение Dice Roller

Если приложение ещё не создано, соберите его. Файл `App.tsx`:

```tsx
import { StatusBar } from 'expo-status-bar';
import { useState } from 'react';
import { Pressable, StyleSheet, Text, View } from 'react-native';

function rollDice(): number {
  return Math.floor(Math.random() * 6) + 1;
}

export default function App() {
  const [result, setResult] = useState(1);

  return (
    <View style={styles.container}>
      <Text style={styles.title}>Dice Roller</Text>
      <Text style={styles.result}>{result}</Text>
      <Pressable style={styles.button} onPress={() => setResult(rollDice())}>
        <Text style={styles.buttonText}>Бросить кубик</Text>
      </Pressable>
      <StatusBar style="auto" />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#F5F5F5',
    alignItems: 'center',
    justifyContent: 'center',
  },
  title: {
    fontSize: 28,
    fontWeight: 'bold',
    marginBottom: 24,
  },
  result: {
    fontSize: 64,
    fontWeight: 'bold',
    color: '#0057B8',
    marginBottom: 24,
  },
  button: {
    backgroundColor: '#0057B8',
    paddingHorizontal: 32,
    paddingVertical: 14,
    borderRadius: 12,
  },
  buttonText: {
    color: '#FFFFFF',
    fontSize: 18,
  },
});
```

Внешне приложение работает правильно, но внутри могут происходить ошибки: число не меняется, кнопка не реагирует, экран остаётся пустым. Чтобы понять причину, нужно заглянуть внутрь работающего приложения — этим и занимается отладка.

## Что такое отладка

**Отладчик** — это инструмент, который позволяет управлять выполнением кода: приостанавливать его в нужном месте, шаг за шагом продвигаться по строкам и смотреть значения переменных. С его помощью можно найти ошибку, а не догадываться о её причине.

## Вывод в консоль: console.log

Самый простой способ понять, что происходит в коде, — выводить значения в консоль с помощью `console.log`:

```tsx
function rollDice(): number {
  const value = Math.floor(Math.random() * 6) + 1;
  console.log('Выпало:', value);
  return value;
}
```

Каждый вызов `console.log` печатает сообщение в консоль. Здесь достаточно просто передать значения, без указания тега.

## Где смотреть консоль

Вывод `console.log` отображается в двух местах:

1. **В терминале**, где запущен `npx expo start` — там появляются сообщения от приложения, в том числе при запуске на телефоне в Expo Go.
2. **В консоли браузера** при запуске в веб-режиме (`npx expo start --web`): откройте инструменты разработчика клавишей `F12` и перейдите на вкладку **Console**.

Сообщения в терминале удобно фильтровать по тексту: например, если искать `Выпало`, будут видны только строки из `rollDice`.

## Точки останова в браузере

В веб-режиме доступен полноценный отладчик браузера:

1. Запустите приложение: `npx expo start --web`.
2. Откройте инструменты разработчика (`F12`).
3. Перейдите на вкладку **Sources**.
4. Найдите файл `App.tsx` в дереве исходников.
5. Кликните по номеру строки, чтобы установить **точку останова** (breakpoint).

Когда выполнение дойдёт до этой строки, программа остановится. В панели справа можно посмотреть значения переменных, а кнопками сверху — продолжить выполнение или пройти по шагам:

- **Resume** — продолжить выполнение.
- **Step over** — выполнить текущую строку и перейти к следующей.
- **Step into** — зайти внутрь вызываемой функции.
- **Step out** — выйти из текущей функции на уровень выше.

Попробуйте: поставьте точку останова на строке `const value = ...` в функции `rollDice`, нажмите в приложении «Бросить кубик» и посмотрите значение `value` в панели отладчика.

## Оператор debugger

Точку останова можно задать прямо в коде с помощью оператора `debugger`:

```tsx
function rollDice(): number {
  const value = Math.floor(Math.random() * 6) + 1;
  debugger; // выполнение остановится здесь
  return value;
}
```

Это удобно, когда нужное место в коде легко указать изнутри, а не искать в дереве исходников. Не забудьте удалить оператор `debugger` из готового кода: в релизной сборке он не нужен.

## Точки останова в VS Code

VS Code также умеет отлаживать приложения React Native. Для этого используется расширение **React Native Tools** и конфигурация отладки:

1. Установите расширение React Native Tools.
2. Перейдите на вкладку **Run and Debug** (`Ctrl+Shift+D`).
3. Выберите конфигурацию «Attach to Metro / Expo».
4. Запустите приложение, затем нажмите кнопку запуска отладки.
5. Устанавливайте точки останова кликом в желобе слева от номера строки.

Панель **Variables** показывает значения переменных в текущей точке, а панель **Watch** позволяет следить за конкретными выражениями. Например, добавьте в Watch выражение `value` — и увидите, как оно меняется при каждом броске.

## React DevTools

Для исследования структуры компонентов используют **React DevTools**. В Expo они вызываются через меню терминала: после запуска `npx expo start` нажмите `m`, чтобы открыть меню разработчика, и выберите пункт для React DevTools.

В React DevTools можно:

- просматривать дерево компонентов;
- выделять компонент и видеть его свойства (props);
- редактировать значения в реальном времени.

Например, выделите компонент `App` и найдите в свойствах состояние `result` — DevTools покажет, как оно меняется после каждого броска кубика.

## Практика: исследуем приложение

1. Добавьте `console.log` в функцию `rollDice` и запустите приложение.
2. Нажмите «Бросить кубик» несколько раз и посмотрите вывод в терминале.
3. Установите точку останова на строке с `return value`.
4. Нажмите кнопку ещё раз — выполнение остановится на точке останова.
5. Найдите переменную `value` в панели **Variables** и убедитесь, что число от 1 до 6.
6. Нажмите **Resume** и повторите бросок: значение в панели изменится.

Так отладчик помогает увидеть реальные значения переменных в момент выполнения, а не после того, как приложение уже отработало.

## Меню разработчика в Expo Go

При запуске на телефоне приложение можно перезагрузить без остановки сервера. Для этого встряхните телефон — откроется **меню разработчика** Expo Go. В нём есть:

- **Reload** — перезагрузить приложение (полезно, если экран «завис» после ошибки).
- **Toggle Performance Monitor** — показать частоту кадров и загрузку памяти.
- **Open JS Debugger** — открыть отладчик браузера, подключённый к приложению на телефоне.

Если встряхнуть телефон не получается, перейдите в терминал с запущенным `npx expo start` и нажмите `m` — меню разработчика откроется тем же способом.

## Проверка типов TypeScript

Некоторые ошибки можно найти ещё до запуска приложения. TypeScript проверяет весь проект командой:

```bash
npx tsc --noEmit
```

Если ошибок нет, команда ничего не выводит. Любое сообщение — это найденная проблема: в нём указаны файл, строка и описание. Исправьте ошибку и запустите проверку снова.

## Распространённые ошибки и их признаки

| Признак | Возможная причина |
|:--------|:------------------|
| Белый экран без ошибок | ошибка в разметке или стилях |
| «Undefined is not a function» | вызов несуществующей функции |
| «Cannot read property ... of undefined» | обращение к свойству `undefined` |
| Изображение не отображается | неверный путь в `require` |
| Текст не появился на экране | текст выведен без компонента `Text` |

При появлении ошибки внимательно читайте сообщение: в нём указан файл и строка, где произошла ошибка.

## Резюме

- `console.log` выводит значения в консоль.
- Консоль видна в терминале Expo и в браузере.
- Точки останова ставятся в браузере (вкладка Sources) или в VS Code.
- Оператор `debugger` останавливает выполнение прямо из кода.
- Кнопки Resume, Step over, Step into и Step out управляют выполнением программы.
- React DevTools помогает исследовать дерево компонентов и их свойства.
