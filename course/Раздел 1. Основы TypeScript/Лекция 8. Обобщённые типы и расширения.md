# Лекция 8. Обобщённые типы и расширения

Иногда один и тот же код повторяется, и меняется только тип данных: вопрос викторины хранит ответ-строку, ответ-число или ответ-логическое значение. Копировать класс ради одного типа неудобно. TypeScript решает эту задачу **обобщёнными типами** (дженериками) - они позволяют описать тип один раз, а конкретный тип подставить при использовании.

Кроме этого, TypeScript позволяет расширять существующие типы: интерфейсы наследуют друг друга, классы - тоже, а utility-типы создают новые типы на основе уже существующих.

## Что вы узнаете

- Что такое обобщённые типы и зачем они нужны.
- Как объявлять обобщённые классы и функции (`<T>`).
- Как ограничивать обобщённый тип через `extends`.
- Как использовать utility-типы `Partial`, `Pick`, `Omit`.
- Как расширять интерфейсы и наследовать классы.

## Проблема повторяющихся типов

Представьте приложение-викторину. Вопросы бывают разных типов: с ответом-словом, «верно или неверно» и с числовым ответом. Каждый вопрос описывается отдельным типом:

```ts
type FillInTheBlankQuestion = {
  questionText: string
  answer: string
  difficulty: string
}

type TrueOrFalseQuestion = {
  questionText: string
  answer: boolean
  difficulty: string
}

type NumericQuestion = {
  questionText: string
  answer: number
  difficulty: string
}
```

Все три типа одинаковы, кроме типа свойства `answer`. Каждый новый вид вопроса заставит копировать описание заново, а исправление приходилось бы вносить во все типы сразу. Обобщённый тип решает эту задачу одним объявлением.

## Обобщённый класс

Обобщённый тип записывается в угловых скобках после имени класса. Имя-заместитель (`T` - от слова type) можно использовать везде, где нужен тип данных:

```ts
class Question<T> {
  questionText: string
  answer: T
  difficulty: string

  constructor(questionText: string, answer: T, difficulty: string) {
    this.questionText = questionText
    this.answer = answer
    this.difficulty = difficulty
  }
}
```

Конкретный тип указывается при создании объекта:

```ts
const question1 = new Question<string>("Ворон промолвил: ___", "никогда", "средне")
const question2 = new Question<boolean>("Небо зелёное. Верно или нет?", false, "легко")
const question3 = new Question<number>("Сколько дней между полнолуниями?", 28, "тяжело")
```

TypeScript умеет выводить `T` из аргумента, поэтому запись `new Question<string>(...)` можно сократить до `new Question(...)` - тип будет определён по значению `answer`.

## Обобщённые функции

Обобщёнными бывают и функции:

```ts
function firstOrUndefined<T>(items: T[]): T | undefined {
  return items.length > 0 ? items[0] : undefined
}

console.log(firstOrUndefined([1, 2, 3]))    // 1
console.log(firstOrUndefined(["а", "б"]))   // а
console.log(firstOrUndefined([]))           // undefined
```

Одна функция работает с массивом любого типа, а `T` каждый раз подставляется автоматически. Обратите внимание на `T | undefined` - функции вроде этой честно сообщают, что результата может и не быть.

## Ограничения обобщённого типа

Иногда внутри обобщённой функции нужно быть уверенным, что у значения есть определённые свойства. Для этого тип ограничивают ключевым словом `extends`:

```ts
interface HasId {
  id: string
}

function findById<T extends HasId>(items: T[], id: string): T | undefined {
  return items.find((item) => item.id === id)
}
```

`<T extends HasId>` означает: «`T` - любой тип, но у него обязательно должно быть свойство `id`». Без ограничения обратиться к `item.id` нельзя - TypeScript выдаст ошибку ещё при проверке типов.

Ограничение может описывать не интерфейс, а требование к самому типу:

```ts
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b
}

console.log(longest("привет", "мир"))     // привет
console.log(longest([1, 2, 3], [4, 5]))   // [ 1, 2, 3 ]
```

## Utility-типы: Partial, Pick, Omit

В TypeScript есть готовые обобщённые типы, которые создают новый тип из существующего. Они называются **utility-типами** и часто используются в реальном коде.

**`Partial<T>`** делает все свойства необязательными:

```ts
type QuestionPreview = Partial<Question<string>>

const preview: QuestionPreview = { questionText: "Ворон промолвил: ___" }
```

Такой тип удобен, когда объект заполняется постепенно или обновляется частично.

**`Pick<T, K>`** оставляет только перечисленные свойства:

```ts
type QuestionHeader = Pick<Question<string>, "questionText" | "difficulty">

const header: QuestionHeader = {
  questionText: "Ворон промолвил: ___",
  difficulty: "средне",
}
```

**`Omit<T, K>`** наоборот, убирает перечисленные свойства:

```ts
type QuestionWithoutAnswer = Omit<Question<string>, "answer">

const card: QuestionWithoutAnswer = {
  questionText: "Ворон промолвил: ___",
  difficulty: "средне",
}
```

Utility-типы хорошо сочетаются друг с другом и с обобщёнными функциями. Например, функция частичного обновления:

```ts
function update<T>(item: T, changes: Partial<T>): T {
  return { ...item, ...changes }
}
```

Запись `{ ...item, ...changes }` создаёт новый объект: сначала копируются свойства `item`, затем поверх них - изменения из `changes`.

## Расширение интерфейсов

Интерфейс может наследовать другой интерфейс и добавлять свои свойства:

```ts
interface QuizItem {
  questionText: string
  difficulty: string
}

interface AnswerableQuestion<T> extends QuizItem {
  answer: T
}
```

`AnswerableQuestion<T>` получает свойства `questionText` и `difficulty` от `QuizItem`, а также добавляет `answer` с типом `T`. Расширять можно сразу несколько интерфейсов: `interface A extends B, C`.

Класс реализует такой интерфейс через `implements` - это показано в программе в конце лекции.

## Наследование классов

Классы расширяются ключевым словом `extends`, причём базовый класс тоже может быть обобщённым:

```ts
abstract class QuizItemBase {
  questionText: string
  difficulty: string

  constructor(questionText: string, difficulty: string) {
    this.questionText = questionText
    this.difficulty = difficulty
  }

  abstract describe(): string
}

class Question<T> extends QuizItemBase {
  answer: T

  constructor(questionText: string, answer: T, difficulty: string) {
    super(questionText, difficulty)
    this.answer = answer
  }

  override describe(): string {
    return `${super.describe()} - ответ: ${String(this.answer)}`
  }
}
```

- `abstract` - класс или метод без реализации; наследник обязан реализовать `abstract`-метод.
- `super(...)` - вызов конструктора родителя.
- `super.describe()` - вызов реализации родителя.
- `override` - пометка переопределённого метода.

## Программа целиком

Создайте файл `main.ts`:

```ts
interface QuizItem {
  questionText: string
  difficulty: string
}

interface AnswerableQuestion<T> extends QuizItem {
  answer: T
}

class Question<T> implements AnswerableQuestion<T> {
  questionText: string
  answer: T
  difficulty: string

  constructor(questionText: string, answer: T, difficulty: string) {
    this.questionText = questionText
    this.answer = answer
    this.difficulty = difficulty
  }

  describe(): string {
    return `${this.questionText} - ответ: ${String(this.answer)}`
  }
}

function update<T>(item: T, changes: Partial<T>): T {
  return { ...item, ...changes }
}

const questions: Question<unknown>[] = [
  new Question<string>("Ворон промолвил: ___", "никогда", "средне"),
  new Question<boolean>("Небо зелёное. Верно или нет?", false, "легко"),
  new Question<number>("Сколько дней между полнолуниями?", 28, "тяжело"),
]

questions.forEach((question) => {
  console.log(`${question.describe()} (${question.difficulty})`)
})

const updated = update(questions[0], { difficulty: "легко" })
console.log(`Обновлено: ${updated.difficulty}`)
```

Запустите:

```bash
node main.ts
```

Вывод:

```
Ворон промолвил: ___ - ответ: никогда (средне)
Небо зелёное. Верно или нет? - ответ: false (легко)
Сколько дней между полнолуниями? - ответ: 28 (тяжело)
Обновлено: легко
```

## Резюме

- Обобщённый тип (`<T>`) позволяет описать класс или функцию один раз для разных типов данных.
- Конкретный тип подставляется при вызове или при создании объекта, а часто выводится автоматически.
- Ограничение `<T extends ...>` требует, чтобы у типа были нужные свойства.
- `Partial`, `Pick`, `Omit` создают новый тип на основе существующего.
- Интерфейсы расширяются через `extends`, классы - через `extends` и `implements`.
- `abstract` задаёт обязательный для реализации метод, `super` обращается к родителю, `override` помечает переопределение.
