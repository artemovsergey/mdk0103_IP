# Лекция 4. Null и undefined

До сих пор каждая переменная в наших программах имела значение. Но в реальных приложениях значение часто отсутствует: пользователь ещё не выбрал любимого актёра, поиск ничего не нашёл, поле формы не заполнено. В TypeScript для отсутствующего значения есть два специальных типа - `null` и `undefined`.

Если обращаться с ними неаккуратно, приложение падает с ошибкой во время работы. TypeScript помогает этого избежать: компилятор заставляет явно проверять, есть ли значение. На этом занятии вы научитесь объявлять переменные, которые могут не иметь значения, и безопасно с ними работать.

## Что вы узнаете

- Что такое `null` и `undefined` и чем они отличаются.
- Как строгий режим TypeScript защищает от ошибок.
- Как объявить переменную, которая может не иметь значения.
- Как безопасно обращаться к таким переменным: `?.`, `??` и `if`.
- Почему оператор `!` требует осторожности.

## Что вам понадобится

- Компьютер с установленным Node.js (версия LTS) и редактор VS Code (см. файл «Настройка окружения Expo»).
- Файл `main.ts` для примеров. Запуск: `node main.ts`.
- В `tsconfig.json` должен быть включён строгий режим: `"strict": true` (в проекте Expo он включён по умолчанию).

## Значение, которого нет

`null` и `undefined` означают отсутствие значения, но немного по-разному:

- **`undefined`** - значение не задано: переменная объявлена, но в неё ничего не записали.
- **`null`** - значение сознательно отсутствует: программист явно записал «здесь ничего нет».

`undefined` встречается сам собой в нескольких ситуациях:

```ts
let nickname
console.log(nickname)   // undefined - значение не присвоено

const planets = ["Меркурий", "Венера", "Земля"]
console.log(planets[10])   // undefined - элемента с таким индексом нет

function printLine(): void {
  console.log("----------")
}

console.log(printLine())   // undefined - функция ничего не вернула
```

`null` же записывают в переменную вручную, чтобы показать, что значения нет:

```ts
let favoriteActor: string | null = "Сандра О"
console.log(favoriteActor)   // Сандра О

favoriteActor = null
console.log(favoriteActor)   // null
```

Запись `string | null` читается как «строка или null» и называется **объединением типов** (union). О ней - чуть ниже.

## Строгий режим и безопасность типов

По умолчанию TypeScript разрешает присвоить `null` переменной любого типа. Если потом обратиться к её свойству, приложение упадёт во время выполнения:

```
TypeError: Cannot read properties of null (reading 'length')
```

Такие ошибки трудно искать: программа компилируется без замечаний и падает только на конкретных данных. Поэтому в новых проектах включают строгий режим (`"strict": true`), при котором `null` и `undefined` нельзя присвоить обычному типу:

```ts
let favoriteActor: string = "Сандра О"
favoriteActor = null   // Ошибка типа: значение null не подходит для string
```

Компилятор требует заранее сказать, что переменная может быть пустой. Это называется **безопасностью типов**: сначала проверяем значение - потом используем.

## Переменные, которые могут быть пустыми

Чтобы разрешить переменной хранить отсутствующее значение, к её типу добавляют `| null` или `| undefined`:

```ts
let favoriteActor: string | null = "Сандра О"
let nickname: string | undefined
```

Тип `string | null` означает «строка или null», а `string | undefined` - «строка или undefined». Внутри `if` TypeScript сам понимает, какой из вариантов сейчас действует, - это называется **сужением типа**:

```ts
let favoriteActor: string | null = "Сандра О"

if (favoriteActor !== null) {
  console.log(favoriteActor.length)   // здесь favoriteActor - точно string
} else {
  console.log("Актёр не указан")
}
```

Внутри ветки `if` компилятор знает, что значение не пустое, поэтому обращение к `length` разрешено.

## Обращение к пустой переменной

Если попытаться обратиться к свойству переменной, которая может быть `null`, компилятор выдаст ошибку ещё до запуска:

```ts
let favoriteActor: string | null = "Сандра О"

console.log(favoriteActor.length)   // Ошибка типа: значение может быть null
```

Это защита: неизвестно, есть ли значение в переменной, а обращение к свойству пустого значения приводит к падению программы. Дальше - три способа безопасной работы.

## Оператор безопасного вызова ?.

Оператор **`?.`** обращается к свойству или методу, только если значение не пустое. Если значение `null` или `undefined`, выражение возвращает `undefined` вместо ошибки:

```ts
let favoriteActor: string | null = "Сандра О"
console.log(favoriteActor?.length)   // 9

favoriteActor = null
console.log(favoriteActor?.length)   // undefined - программа не падает
```

Сравните: `favoriteActor.length` при `null` приведёт к аварийному завершению, а `favoriteActor?.length` просто вернёт `undefined`.

Оператор удобно применять для методов:

```ts
const text: string | null = null

console.log(text?.toUpperCase())   // undefined
```

Цепочку `?.` можно продолжать для вложенных объектов:

```ts
type Company = { name: string; address?: { city?: string } }

const company: Company = { name: "Колледж" }
console.log(company.address?.city)   // undefined - адрес не указан
```

## Оператор нулевого слияния ??

Оператор **`??`** подставляет значение по умолчанию, если слева оказались `null` или `undefined`:

```ts
let favoriteActor: string | null = null

const lengthOfName = favoriteActor?.length ?? 0
console.log(lengthOfName)   // 0
```

Читается так: «взять длину имени, а если её нет - взять 0». Если значение есть, оператор возвращает его.

`??` похож на оператор `||`, но между ними есть важное различие: `||` заменяет и `0`, и пустую строку `""`, потому что считает их ложными:

```ts
const count = 0

console.log(count || 10)   // 10 - неверно, если 0 - допустимое число
console.log(count ?? 10)   // 0  - верно
```

Для значений, которые могут быть пустыми, используйте `??`.

## Оператор утверждения !

Оператор **`!`** говорит компилятору: «я уверен, что значение не пустое». Проверка типа отключается:

```ts
let favoriteActor: string | null = "Сандра О"

console.log(favoriteActor!.length)   // 9
```

Если уверенность ошибочна, программа упадёт:

```ts
favoriteActor = null
console.log(favoriteActor!.length)
```

```
TypeError: Cannot read properties of null (reading 'length')
```

Оператор `!` используют редко - только когда значение точно не может быть пустым. В остальных случаях выбирайте `?.`, `??` или проверку через `if`.

## Проверка через if

Когда значение нужно использовать несколько раз, удобнее проверить его один раз и дальше работать как с обычной строкой:

```ts
let favoriteActor: string | null = "Сандра О"

if (favoriteActor !== null) {
  console.log(`В имени ${favoriteActor.length} символов.`)
  console.log(favoriteActor.toUpperCase())
} else {
  console.log("Имя не указано.")
}
```

Внутри ветки `if` сужение типа работает и для `undefined`:

```ts
let city: string | undefined

if (city !== undefined) {
  console.log(city.toUpperCase())
} else {
  console.log("Город не указан.")
}
```

Коротко правило такое: одна ссылка на пустую переменную - используйте `?.`; несколько строк с ней - проверьте через `if`.

## Значение по умолчанию и тернарный оператор

Значение по умолчанию можно получить и без `??` - через тернарный оператор:

```ts
let favoriteActor: string | null = null

const lengthOfName = favoriteActor !== null ? favoriteActor.length : 0
console.log(lengthOfName)   // 0
```

Запись `favoriteActor?.length ?? 0` короче и делает то же самое.

## Необязательные параметры

Вспомните параметры по умолчанию из лекции «Функции». Необязательный параметр обозначается знаком `?` и имеет тип «значение или `undefined`»:

```ts
function greet(name?: string): void {
  console.log(`Привет, ${name ?? "Гость"}!`)
}

greet()          // Привет, Гость!
greet("Иван")    // Привет, Иван!
```

Необязательные свойства объектов объявляются так же:

```ts
type User = {
  name: string
  city?: string
}

const user: User = { name: "Мария" }
console.log(user.city ?? "Город не указан")   // Город не указан
```

## Программа целиком

Соберём всё вместе. Создайте файл `main.ts`:

```ts
let favoriteActor: string | null = "Сандра О"

const lengthOfName = favoriteActor?.length ?? 0
console.log(`Символов в имени: ${lengthOfName}`)

favoriteActor = null

if (favoriteActor !== null) {
  console.log(`Символов в имени: ${favoriteActor.length}`)
} else {
  console.log("Любимый актёр не указан.")
}
```

Запустите:

```bash
node main.ts
```

Вывод:

```
Символов в имени: 9
Любимый актёр не указан.
```

Разберём программу:

- `favoriteActor?.length ?? 0` безопасно получает длину имени и подставляет `0`, если имени нет.
- После `favoriteActor = null` переменная снова пустая - это допустимо, ведь её тип `string | null`.
- Проверка `if (favoriteActor !== null)` отделяет случай с именем от случая без имени.

## Резюме

- `undefined` - значение не задано, `null` - значение отсутствует намеренно.
- В строгом режиме `null` и `undefined` нельзя присвоить обычному типу.
- Пустые значения объявляются через объединение типов: `string | null`, `string | undefined`.
- Оператор `?.` безопасно обращается к свойству и возвращает `undefined`, если значения нет.
- Оператор `??` подставляет значение по умолчанию вместо `null` и `undefined`.
- Оператор `!` отключает проверку и может привести к ошибке во время выполнения - используйте его редко.
- Проверка через `if` сужает тип: внутри ветки с пустым значением уже можно работать как с обычным.
