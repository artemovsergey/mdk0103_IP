## Зачем нужны автоматизированные тесты

Тестирование программного обеспечения — это структурированный метод проверки того, что программа работает так, как ожидается. Автоматизированный тест — это код, который проверяет поведение другого кода.

Зачем писать тесты:

- Они быстро находят ошибки после изменений в коде.
- Позволяют смело рефакторить: если тесты проходят, поведение приложения сохранено.
- Заменяют многократную ручную проверку одних и тех же сценариев.

## Принцип AAA

Каждый хороший тест состоит из трёх частей:

- **Arrange (подготовка)** — отрисовать компонент, найти нужные элементы, подготовить данные.
- **Act (действие)** — выполнить действие пользователя: ввести текст, нажать кнопку.
- **Assert (проверка)** — убедиться, что результат совпадает с ожидаемым.

## Шаг 1. Установка Jest

В папке проекта выполните команду:

```bash
npm install --save-dev jest-expo jest @types/jest @testing-library/react-native
```

- `jest` — среда запуска тестов.
- `jest-expo` — пресет Jest для проектов Expo: учит Jest понимать React Native и Expo.
- `@types/jest` — типы TypeScript для функций `describe`, `test` и `expect`.
- `@testing-library/react-native` — библиотека для отрисовки компонентов и имитации действий пользователя.

## Шаг 2. Настройка package.json

Добавьте команду запуска тестов и пресет в `package.json` (остальные поля оставьте без изменений):

```json
{
  "scripts": {
    "test": "jest"
  },
  "jest": {
    "preset": "jest-expo"
  }
}
```

## Шаг 3. Тестовый файл

Тесты размещают в папке `__tests__` в корне проекта — Jest находит её автоматически. Создайте файл `__tests__/App.test.tsx` и начните с импортов и группы `describe`:

```tsx
import { fireEvent, render, screen } from '@testing-library/react-native'

import App from '../App'

describe('Tip Time', () => {
  // здесь будут четыре теста
})
```

- `render` — отрисовывает компонент в виртуальном дереве.
- `screen` — даёт доступ к элементам на экране.
- `fireEvent` — имитирует действия пользователя.

## Шаг 4. Тест 1: приложение рендерится

```tsx
  test('отображает подпись «Счёт» при запуске', () => {
    // Arrange: отрисовать приложение
    render(<App />)

    // Assert: подпись «Счёт» видна на экране
    expect(screen.getByText('Счёт')).toBeTruthy()
  })
```

`getByText` находит элемент по видимому тексту и выбрасывает ошибку, если элемент не найден, — значит, тест проверяет, что экран отрисовался.

## Шаг 5. Тест 2: расчёт после нажатия кнопки

```tsx
  test('рассчитывает чаевые после нажатия кнопки', () => {
    // Arrange: отрисовать приложение
    render(<App />)

    // Act: ввести сумму и нажать «Рассчитать»
    fireEvent.changeText(screen.getByPlaceholderText('Например, 1000'), '1000')
    fireEvent.press(screen.getByText('Рассчитать'))

    // Assert: появились чаевые (15 %) и итог
    expect(screen.getByText('Сумма чаевых: 150.00 ₽')).toBeTruthy()
    expect(screen.getByText('Итог: 1150.00 ₽')).toBeTruthy()
  })
```

`fireEvent.changeText` имитирует ввод текста, `fireEvent.press` — нажатие. По умолчанию выбран процент 15, поэтому от 1000 чаевые равны 150, а итог — 1150.

## Шаг 6. Тест 3: пустое поле

```tsx
  test('не рассчитывает чаевые при пустом поле', () => {
    // Arrange: отрисовать приложение
    render(<App />)

    // Act: нажать «Рассчитать», ничего не вводя
    fireEvent.press(screen.getByText('Рассчитать'))

    // Assert: показана подсказка, результата нет
    expect(screen.getByText('Введите сумму счёта')).toBeTruthy()
    expect(screen.queryByText(/Сумма чаевых/)).toBeNull()
  })
```

`queryByText` в отличие от `getByText` не выбрасывает ошибку, а возвращает `null`, если элемент не найден. Именно он подходит для проверки, что результата **нет**.

## Шаг 7. Тест 4: смена процента чаевых

```tsx
  test('переключение процента чаевых меняет результат', () => {
    // Arrange: отрисовать приложение и ввести сумму
    render(<App />)
    fireEvent.changeText(screen.getByPlaceholderText('Например, 1000'), '1000')

    // Act: выбрать 20 % и нажать «Рассчитать»
    fireEvent.press(screen.getByText('20%'))
    fireEvent.press(screen.getByText('Рассчитать'))

    // Assert: 20 % от 1000 равны 200
    expect(screen.getByText('Сумма чаевых: 200.00 ₽')).toBeTruthy()
  })
```

## Полный код файла __tests__/App.test.tsx

```tsx
import { fireEvent, render, screen } from '@testing-library/react-native'

import App from '../App'

describe('Tip Time', () => {
  test('отображает подпись «Счёт» при запуске', () => {
    render(<App />)

    expect(screen.getByText('Счёт')).toBeTruthy()
  })

  test('рассчитывает чаевые после нажатия кнопки', () => {
    render(<App />)

    fireEvent.changeText(screen.getByPlaceholderText('Например, 1000'), '1000')
    fireEvent.press(screen.getByText('Рассчитать'))

    expect(screen.getByText('Сумма чаевых: 150.00 ₽')).toBeTruthy()
    expect(screen.getByText('Итог: 1150.00 ₽')).toBeTruthy()
  })

  test('не рассчитывает чаевые при пустом поле', () => {
    render(<App />)

    fireEvent.press(screen.getByText('Рассчитать'))

    expect(screen.getByText('Введите сумму счёта')).toBeTruthy()
    expect(screen.queryByText(/Сумма чаевых/)).toBeNull()
  })

  test('переключение процента чаевых меняет результат', () => {
    render(<App />)

    fireEvent.changeText(screen.getByPlaceholderText('Например, 1000'), '1000')
    fireEvent.press(screen.getByText('20%'))
    fireEvent.press(screen.getByText('Рассчитать'))

    expect(screen.getByText('Сумма чаевых: 200.00 ₽')).toBeTruthy()
  })
})
```

## Шаг 8. Запуск тестов

Выполните команду:

```bash
npm test
```

Jest найдёт тестовые файлы и покажет результат:

```text

  Tip Time
    √ отображает подпись «Счёт» при запуске
```

Во время разработки удобно запускать `npm test -- --watch`: Jest будет перезапускать тесты после каждого сохранения файла.

## Тесты проверяют поведение, а не реализацию

В тестах выше нет ни одного обращения к переменным состояния `amountInput`, `result` или к функции `handleCalculate`. Проверяется только то, что видит пользователь: текст на экране и реакция на действия.

Это важно, потому что:

- Внутреннее устройство приложения можно менять — переименовывать состояния, дробить компоненты, менять стили, — и тесты продолжат проходить.
- Если тест «зацепится» за детали реализации, любая перестановка кода будет ломать тесты, хотя поведение не изменилось.
- Тест, описывающий поведение, читается как сценарий: «ввести сумму, нажать кнопку, увидеть 150.00 ₽».

## Резюме

- Автоматизированные тесты проверяют, что приложение работает так, как ожидается.
- Jest и `jest-expo` — стандартный набор для тестирования проектов Expo на TypeScript.
- Установка: `npm install --save-dev jest-expo jest @types/jest @testing-library/react-native`, запуск: `npm test`.
- `render` отрисовывает компонент, `screen` ищет элементы, `fireEvent` имитирует действия пользователя.
- Утверждения `toBeTruthy` и `toBeNull` проверяют найденные элементы.
- Каждый тест строится по принципу AAA: arrange — act — assert.
- Тесты проверяют поведение приложения, а не детали его реализации.
