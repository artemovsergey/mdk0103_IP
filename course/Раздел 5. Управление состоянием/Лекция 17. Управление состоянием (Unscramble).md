# Лекция 17. Управление состоянием (Unscramble)

В лекции 15 вы познакомились с состоянием и хуком `useState`. Пока приложение небольшое, нескольких ячеек состояния достаточно. Но когда приложение растёт, состояние и логика расползаются по компоненту: он раздувается, а проверить правила игры без запуска интерфейса уже невозможно.

На этом занятии вы научитесь управлять состоянием в большом приложении: вынесете логику в собственный хук, соберёте связанные данные в `useReducer` и передадите состояние вглубь дерева компонентов через `Context`. Результатом станет игра **Unscramble**, в которой игрок угадывает зашифрованные слова.

### Необходимые условия

- Знание TypeScript: функции, объекты, массивы.
- Умение создавать состояние через `useState`.
- Базовое представление о компонентах и свойствах (props).

### Что вы узнаете

- Зачем выносить состояние и логику из компонентов.
- Как создать собственный хук.
- Как использовать `useReducer` для связанного состояния.
- Как передать состояние вглубь дерева через `Context`.

### Что вы создадите

Игровое приложение **Unscramble**: зашифрованное слово, поле для ответа, счёт, счётчик слов и экран завершения игры.

## Состояние и логика внутри компонента

Представьте, что вся игра написана в одном компоненте:

```tsx
function UnscrambleApp() {
  const [currentWord, setCurrentWord] = useState('react')
  const [scrambledWord, setScrambledWord] = useState('eactr')
  const [score, setScore] = useState(0)
  // ... ещё десяток состояний и обработчиков
}
```

Такой компонент делает слишком много: хранит данные, описывает правила игры и рисует интерфейс. Проверить начисление очков отдельно от экрана нельзя, а переиспользовать правила игры в другом месте почти нереально. Поэтому состояние и логику выносят в **собственный хук**, а компонент оставляют только для отображения.

## Собственный хук и useReducer

Собственный хук — это функция, имя которой начинается с `use`, а внутри вызываются другие хуки. Когда значений много и они меняются согласованно, десяток `useState` становится неудобным: легко забыть обновить одно из них. На помощь приходит **`useReducer`** — он собирает всё состояние игры в один объект.

Опишите форму состояния игры:

```tsx
type GameState = {
  currentWord: string
  scrambledWord: string
  isGuessed: boolean
  isGuessWrong: boolean
  score: number
  wordCount: number
  isGameOver: boolean
}
```

Изменения описывают **действиями**: `SUBMIT_GUESS`, `SKIP_WORD`, `NEXT_WORD` и `RESTART`. Редьюсер — **чистая функция**: он получает текущее состояние и действие, а возвращает новое состояние, ничего не изменяя напрямую и ничего не рисуя. Редьюсер не вызывается вручную — хук запускает его через `dispatch`. Всё это вы увидите в полном коде в конце лекции.

Преимущества `useReducer`:

- все правила изменения состояния собраны в одном месте;
- редьюсер — чистая функция, его легко тестировать;
- действия описывают, **что произошло**, а не как меняется каждое поле.

## Context: состояние без «прокидывания» props

Состояние игры нужно нескольким компонентам: экрану игры, таблице счёта, экрану завершения. Передавать его через props на каждом уровне неудобно — это называют **«прокидыванием props»** (prop drilling).

**React Context** позволяет положить значение в общий контейнер и достать его в любом компоненте внутри. Создаётся контекст функцией `createContext`, а выдаёт его компонентам функция `useContext`:

```tsx
function ScoreBoard() {
  const { score, wordCount } = useGame()
  return <Text>{`Очки: ${score} · Слов: ${wordCount} / ${MAX_WORDS}`}</Text>
}
```

Компонента `ScoreBoard` не нужно знать, где хранится игра: она получает данные из контекста. В полном коде ниже контейнер `GameProvider` создаёт состояние и кладёт его в контекст, а хук `useGame` выдаёт состояние компонентам. Если компонент забыли обернуть в `GameProvider`, `useGame` подскажет об ошибке.

## Поднятие состояния

Если общие данные нужны лишь двум-трём соседним компонентам, контекст не нужен: состояние **поднимают** в их общего родителя, а детям передают значение и функцию изменения через props (этот приём вы разбирали в лекции 15).

## Что и когда применять

| Инструмент | Когда использовать |
|:--|:--|
| `useState` | одно-два независимых значения |
| `useReducer` | много связанных значений, изменения описываются действиями |
| Context | состояние нужно многим компонентам на разных уровнях |
| Поднятие состояния | состояние нужно нескольким соседним компонентам |

## Полный код

Создайте проект Expo и замените содержимое `App.tsx`:

```tsx
import { StatusBar } from 'expo-status-bar'
import { createContext, useContext, useReducer, useState, type ReactNode } from 'react'
import { Button, StyleSheet, Text, TextInput, View } from 'react-native'

const WORDS = [
  'react', 'native', 'program', 'mobile', 'component',
  'state', 'render', 'screen', 'button', 'style',
]
const MAX_WORDS = 10
const SCORE_INCREASE = 20

function scrambleWord(word: string): string {
  const letters = word.split('')
  for (let i = letters.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1))
    const temp = letters[i]
    letters[i] = letters[j]
    letters[j] = temp
  }
  return letters.join('')
}

function isCorrectGuess(guess: string, word: string): boolean {
  return guess.trim().toLowerCase() === word.toLowerCase()
}

type GameState = {
  currentWord: string
  scrambledWord: string
  isGuessed: boolean
  isGuessWrong: boolean
  score: number
  wordCount: number
  isGameOver: boolean
}

type GameAction =
  | { type: 'SUBMIT_GUESS'; guess: string }
  | { type: 'SKIP_WORD' }
  | { type: 'NEXT_WORD' }
  | { type: 'RESTART' }

function createInitialState(): GameState {
  return {
    currentWord: WORDS[0], scrambledWord: scrambleWord(WORDS[0]),
    isGuessed: false, isGuessWrong: false,
    score: 0, wordCount: 1, isGameOver: false,
  }
}

function gameReducer(state: GameState, action: GameAction): GameState {
  switch (action.type) {
    case 'SUBMIT_GUESS':
      return isCorrectGuess(action.guess, state.currentWord)
        ? {
            ...state,
            score: state.score + SCORE_INCREASE,
            isGuessed: true,
            isGuessWrong: false,
          }
        : { ...state, isGuessWrong: true }
    case 'SKIP_WORD':
      return { ...state, isGuessed: true, isGuessWrong: false }
    case 'NEXT_WORD': {
      if (state.wordCount >= MAX_WORDS) {
        return { ...state, isGameOver: true }
      }
      const nextWord = WORDS[state.wordCount % WORDS.length]
      return {
        ...state,
        currentWord: nextWord,
        scrambledWord: scrambleWord(nextWord),
        isGuessed: false,
        isGuessWrong: false,
        wordCount: state.wordCount + 1,
      }
    }
    case 'RESTART':
      return createInitialState()
    default:
      return state
  }
}

function useUnscrambleGame() {
  const [state, dispatch] = useReducer(gameReducer, createInitialState())

  return {
    ...state,
    submitGuess: (guess: string) => dispatch({ type: 'SUBMIT_GUESS', guess }),
    skipWord: () => dispatch({ type: 'SKIP_WORD' }),
    nextWord: () => dispatch({ type: 'NEXT_WORD' }),
    restart: () => dispatch({ type: 'RESTART' }),
  }
}

const GameContext = createContext<ReturnType<typeof useUnscrambleGame> | null>(null)

function GameProvider({ children }: { children: ReactNode }) {
  const game = useUnscrambleGame()
  return <GameContext.Provider value={game}>{children}</GameContext.Provider>
}

function useGame() {
  const game = useContext(GameContext)
  if (!game) {
    throw new Error('useGame должен вызываться внутри GameProvider')
  }
  return game
}

function ScoreBoard() {
  const { score, wordCount } = useGame()
  return <Text style={styles.score}>{`Очки: ${score} · Слов: ${wordCount} / ${MAX_WORDS}`}</Text>
}

function UnscrambleScreen() {
  const { scrambledWord, isGuessed, isGuessWrong, isGameOver, score, submitGuess, skipWord, nextWord, restart } =
    useGame()
  const [guess, setGuess] = useState('')

  if (isGameOver) {
    return (
      <View style={styles.container}>
        <Text style={styles.title}>Игра завершена</Text>
        <Text style={styles.score}>{`Ваш результат: ${score} очков`}</Text>
        <Button title="Играть снова" onPress={restart} />
      </View>
    )
  }

  return (
    <View style={styles.container}>
      <ScoreBoard />
      <Text style={styles.word}>{scrambledWord}</Text>
      <TextInput
        style={styles.input}
        value={guess}
        onChangeText={setGuess}
        editable={!isGuessed}
        autoCapitalize="none"
        placeholder="Ваш ответ"
      />
      {isGuessWrong && <Text style={styles.error}>Неверно, попробуйте ещё раз</Text>}
      {isGuessed ? (
        <Button
          title="Следующее слово"
          onPress={() => {
            setGuess('')
            nextWord()
          }}
        />
      ) : (
        <View style={styles.buttons}>
          <Button title="Проверить" onPress={() => submitGuess(guess)} />
          <Button
            title="Пропустить"
            onPress={() => {
              setGuess('')
              skipWord()
            }}
          />
        </View>
      )}
    </View>
  )
}

export default function App() {
  return (
    <GameProvider>
      <UnscrambleScreen />
      <StatusBar style="auto" />
    </GameProvider>
  )
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: 'center', justifyContent: 'center', padding: 24, gap: 12 },
  title: { fontSize: 24, fontWeight: 'bold' },
  score: { fontSize: 16 },
  word: { fontSize: 32, fontWeight: 'bold', letterSpacing: 4 },
  input: { alignSelf: 'stretch', borderWidth: 1, borderColor: '#CCCCCC', borderRadius: 8, padding: 12, fontSize: 16 },
  error: { color: '#C62828' },
  buttons: { alignSelf: 'stretch', gap: 8 },
})
```

Разберём ключевые моменты:

- `scrambleWord` перемешивает буквы так, что ни одна не теряется и не добавляется: игра всегда разрешима.
- `gameReducer` не изменяет `state`, а возвращает копию с новыми значениями — состояние остаётся неизменяемым.
- `GameProvider` создаёт состояние один раз для всего дерева, а `useGame` отдаёт его любому компоненту внутри.

## Резюме

- Логику приложения отделяют от представления: компонент рисует, хук хранит состояние и правила.
- Собственный хук — функция с именем на `use`, внутри которой вызываются другие хуки.
- `useReducer` подходит для связанного состояния, а редьюсер — чистая функция, удобная для тестов.
- Context передаёт состояние вглубь дерева компонентов без «прокидывания» props.
- Поднятие состояния помогает, когда данные нужны нескольким соседним компонентам.
