# Практическая работа 22. Unit-тестирование (Unscramble)

В практических работах 15 и 18 вы писали тесты, которые отрисовывали приложение и имитировали действия пользователя. Такие тесты проверяют поведение целиком. В этой работе вы научитесь тестировать **логику отдельно от интерфейса**: чистые функции и собственный хук игры `Unscramble` из лекции 17.

### Необходимые условия

- Приложение `Unscramble` из лекции 17.
- Настроенный Jest из практической работы 15.

### Что вы узнаете

- Зачем тестировать логику отдельно от интерфейса.
- Как писать тесты для чистых функций и редьюсера.
- Как тестировать собственный хук с помощью `renderHook`.
- Что такое путь успеха, путь ошибки и граничный случай.

### Что вы создадите

Файлы `gameLogic.ts` и `useUnscrambleGame.ts`, а также два набора тестов: `__tests__/gameLogic.test.ts` и `__tests__/useUnscrambleGame.test.ts`.

## Зачем тестировать логику отдельно

В лекции 17 логика игры уже отделена от интерфейса: правила вынесены в функцию `gameReducer` и вспомогательные функции. Чистую функцию проверить просто: результат зависит только от аргументов, а экран не нужен.

Unit-тест (модульный тест) проверяет одну небольшую единицу кода: функцию, редьюсер или хук. Запускаются такие тесты командой `npm test` на компьютере. Хорошая стратегия покрывает три сценария:

- **Путь успеха** — обычный сценарий: игрок отвечает верно, очки начисляются.
- **Путь ошибки** — неверный ввод: счёт не меняется, появляется сообщение об ошибке.
- **Граничный случай** — крайние условия: начальное состояние и последнее (десятое) слово.

## Шаг 1. Настройка Jest

Настройка такая же, как в практической работе 15. Если Jest ещё не установлен, выполните:

```bash

```

```json
  "jest": { "preset": "jest-expo" }
```

## Шаг 2. Вынесение логики в gameLogic.ts

Чтобы логику можно было подключать в тестах, вынесите её из `App.tsx` в новый файл `gameLogic.ts`:

- константы `WORDS`, `MAX_WORDS`, `SCORE_INCREASE`;
- функции `scrambleWord` и `isCorrectGuess`;
- типы `GameState` и `GameAction`;
- функции `createInitialState` и `gameReducer`.

Код остаётся прежним, но каждое объявление получает слово `export`, чтобы его можно было импортировать в тестах:


Так же добавьте `export` к константе `WORDS`, типам `GameState` и `GameAction` и константе `SCORE_INCREASE`.

## Шаг 3. Хук в отдельном файле

Перенесите хук `useUnscrambleGame` в файл `useUnscrambleGame.ts`:

```ts
import { useReducer } from 'react'

import { createInitialState, gameReducer } from './gameLogic'

export function useUnscrambleGame() {
  const [state, dispatch] = useReducer(gameReducer, createInitialState())

  return {
    ...state,
    submitGuess: (guess: string) => dispatch({ type: 'SUBMIT_GUESS', guess }),
    skipWord: () => dispatch({ type: 'SKIP_WORD' }),
    nextWord: () => dispatch({ type: 'NEXT_WORD' }),
    restart: () => dispatch({ type: 'RESTART' }),
  }
}
```

В `App.tsx` подключите модули и удалите перенесённый код:

```tsx
import { MAX_WORDS } from './gameLogic'
import { useUnscrambleGame } from './useUnscrambleGame'
```

## Шаг 4. Тесты чистых функций

Создайте файл `__tests__/gameLogic.test.ts`:

```ts
import {
  MAX_WORDS,
  SCORE_INCREASE,
  createInitialState,
  gameReducer,
  isCorrectGuess,
  scrambleWord,
} from '../gameLogic'

describe('scrambleWord', () => {
  test('возвращает все буквы исходного слова', () => {
    const scrambled = scrambleWord('react')

    // те же буквы, возможно в другом порядке
    expect(scrambled.split('').sort().join('')).toBe('acert')
  })

  test('перемешивает слово при известном случайном числе', () => {
    const random = jest.spyOn(Math, 'random').mockReturnValue(0)
    expect(scrambleWord('react')).toBe('eactr')
    random.mockRestore()
  })
})

describe('isCorrectGuess', () => {
  test('принимает ответ в другом регистре и с пробелами', () => {
    expect(isCorrectGuess('  React ', 'react')).toBe(true)
  })

  test('отклоняет неверный ответ', () => {
    expect(isCorrectGuess('reacts', 'react')).toBe(false)
  })
})

describe('gameReducer', () => {
  test('начисляет очки за правильный ответ', () => {
    const state = createInitialState()
    const next = gameReducer(state, { type: 'SUBMIT_GUESS', guess: state.currentWord })

    expect(next.score).toBe(SCORE_INCREASE)
    expect(next.isGuessed).toBe(true)
    expect(next.isGuessWrong).toBe(false)
  })

  test('не начисляет очки за неверный ответ', () => {
    const state = createInitialState()
    const next = gameReducer(state, { type: 'SUBMIT_GUESS', guess: 'неверно' })

    expect(next.score).toBe(0)
    expect(next.isGuessWrong).toBe(true)
  })

  test('переходит к следующему слову', () => {
    const state = { ...createInitialState(), isGuessed: true }
    const next = gameReducer(state, { type: 'NEXT_WORD' })

    expect(next.wordCount).toBe(2)
    expect(next.isGuessed).toBe(false)
    expect(next.scrambledWord.split('').sort().join('')).toBe(
      next.currentWord.split('').sort().join(''),
    )
  })

  test('завершает игру после десятого слова', () => {
    const state = { ...createInitialState(), wordCount: MAX_WORDS }
    const next = gameReducer(state, { type: 'NEXT_WORD' })

    expect(next.isGameOver).toBe(true)
  })
})
```

Тесты проверяют все три сценария:

- правильный ответ — путь успеха;
- неверный ответ — путь ошибки;
- десятое слово — граничный случай: дальше игра заканчивается.

## Шаг 5. Тесты хука

Хук проверяют функцией `renderHook`: она «отрисовывает» невидимый компонент, который вызывает хук, и отдаёт его результат в поле `result.current`. Действия, меняющие состояние, оборачивают в `act`, чтобы React применил обновления.

Создайте файл `__tests__/useUnscrambleGame.test.ts`:

```tsx
import { act, renderHook } from '@testing-library/react-native'

import { MAX_WORDS, SCORE_INCREASE } from '../gameLogic'
import { useUnscrambleGame } from '../useUnscrambleGame'

describe('useUnscrambleGame', () => {
  test('начинает игру с первого слова и нулевого счёта', () => {
    const { result } = renderHook(() => useUnscrambleGame())
    expect(result.current.score).toBe(0)
    expect(result.current.wordCount).toBe(1)
    expect(result.current.isGuessed).toBe(false)
  })

  test('показывает ошибку при неверном ответе', () => {
    const { result } = renderHook(() => useUnscrambleGame())
    act(() => result.current.submitGuess('неверно'))
    expect(result.current.isGuessWrong).toBe(true)
    expect(result.current.score).toBe(0)
  })

  test('начисляет очки и открывает следующее слово', () => {
    const { result } = renderHook(() => useUnscrambleGame())

    act(() => result.current.submitGuess(result.current.currentWord))
    expect(result.current.score).toBe(SCORE_INCREASE)
    expect(result.current.isGuessed).toBe(true)

    act(() => result.current.nextWord())
    expect(result.current.wordCount).toBe(2)
    expect(result.current.isGuessed).toBe(false)
  })

  test('завершает игру, когда сыграны все слова', () => {
    const { result } = renderHook(() => useUnscrambleGame())

    for (let i = 0; i < MAX_WORDS; i++) {
      act(() => result.current.submitGuess(result.current.currentWord))
      act(() => result.current.nextWord())
    }

    expect(result.current.isGameOver).toBe(true)
    expect(result.current.score).toBe(MAX_WORDS * SCORE_INCREASE)
  })
})
```

Тесты не ищут элементы на экране — они проверяют значения, которые возвращает хук, и вызывают его функции напрямую.

## Резюме

- Unit-тесты проверяют отдельные функции, редьюсеры и хуки — без отрисовки экрана.
- Чистая функция предсказуема: один и тот же аргумент даёт один и тот же результат.
- `renderHook` тестирует собственные хуки, а `act` применяет изменения состояния.
- Стратегия тестирования: путь успеха, путь ошибки, граничный случай.
- Тесты логики дополняют тесты интерфейса из практических работ 15 и 18.
