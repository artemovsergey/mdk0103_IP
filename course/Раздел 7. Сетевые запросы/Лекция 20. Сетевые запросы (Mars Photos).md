## Веб-сервисы и REST

Сервер, который отдаёт данные приложениям по сети, называют **веб-сервисом**. Приложение отправляет запрос по адресу сервиса, а сервер возвращает ответ с данными.

Самый распространённый стиль веб-сервисов — **REST** (Representational State Transfer). В REST каждый ресурс доступен по своему адресу, а действие задаётся HTTP-методом:

- `GET` — получить данные;
- `POST` — создать новые данные;
- `PUT` / `PATCH` — обновить существующие данные;
- `DELETE` — удалить данные.

Например, адрес `https://jsonplaceholder.typicode.com/photos` возвращает список фотографий. Это учебный сервис, который мы будем использовать: он не требует регистрации и ключей.

В этой лекции мы обращаемся к сервису методом `GET` и получаем данные в формате **JSON** (JavaScript Object Notation) — текстовом формате пар «ключ — значение». Вот как выглядит начало ответа:

```json
[
  {
    "albumId": 1,
    "id": 1,
    "title": "accusamus beatae ad facilis cum similique qui sunt",
    "url": "https://via.placeholder.com/600/92c952"
  }
]
```

Ответ содержит массив объектов: у каждого есть номер `id` и адрес фотографии `url`. Остальные поля нам не понадобятся — лишние данные можно просто игнорировать.

## Модель данных

Опишем тип, который соответствует нужным нам полям JSON-ответа:

```tsx
export type MarsPhoto = {
  id: number
  title: string
  url: string
}
```

Тип помогает заметить ошибку ещё при написании кода: если обратиться к несуществующему полю, TypeScript подчеркнёт его красным.

## Адрес и параметры запроса

Адрес ресурса записывают в константу. Дополнительно к адресу можно передавать **параметры запроса** — они идут после знака `?`:

```tsx
const API_URL = 'https://jsonplaceholder.typicode.com/photos?_limit=20'
```

`_limit=20` просит сервер вернуть только 20 записей вместо всех. Сервис jsonplaceholder поддерживает такой параметр, поэтому ответ будет короче и загрузится быстрее.

## Запрос через fetch

Сетевой запрос выполняет встроенная функция **`fetch`**. Она возвращает **промис**, поэтому результат получают через `await` внутри `async`-функции:

```tsx
async function fetchPhotos(): Promise<MarsPhoto[]> {
  const response = await fetch(API_URL)

  if (!response.ok) {
    throw new Error(`Сервер вернул код ${response.status}`)
  }

  return (await response.json()) as MarsPhoto[]
}
```

Разберём по шагам:

1. `await fetch(API_URL)` отправляет запрос и ждёт ответ сервера.
2. `response.ok` равен `true` для кодов 200–299. Если сервер ответил ошибкой, мы сами выбрасываем исключение с кодом.
3. `await response.json()` читает тело ответа и превращает JSON-текст в объекты.
4. `as MarsPhoto[]` подсказывает TypeScript, какие поля есть у объектов.

> `fetch` не завершается ошибкой при коде 404 или 500, поэтому проверять `response.ok` нужно всегда.

## Состояния экрана

Запрос занимает время и может завершиться неудачей. Удобно описать все ситуации одним типом:

```tsx
type UiState =
  | { status: 'loading' }
  | { status: 'success'; photos: MarsPhoto[] }
  | { status: 'error'; message: string }
```

Такой тип называют **объединением** (union): в каждый момент состояние имеет ровно один из трёх видов.

- `loading` — запрос выполняется, на экране индикатор.
- `success` — данные получены, в поле `photos` лежит массив.
- `error` — запрос не удался, в поле `message` лежит текст ошибки.

## Загрузка при открытии экрана

Запрос запускается в `useEffect` с пустым массивом зависимостей — это значит «выполнить один раз после первого показа экрана»:

```tsx
useEffect(() => {
  fetchPhotos()
    .then((photos) => setState({ status: 'success', photos }))
    .catch((error: unknown) =>
      setState({
        status: 'error',
        message: error instanceof Error ? error.message : 'Не удалось загрузить данные',
      }),
    )
}, [])
```

- `then` срабатывает при успехе и сохраняет данные.
- `catch` срабатывает при любой ошибке: недоступен сервер, нет сети, код ответа не `ok`.
- Пустой массив `[]` в конце не даёт запросу повторяться при каждой перерисовке.

## Экран приложения

Экран показывает ровно одно из трёх состояний:

```tsx
function MarsPhotosScreen() {
  const [state, setState] = useState<UiState>({ status: 'loading' })

  useEffect(() => {
    fetchPhotos()
      .then((photos) => setState({ status: 'success', photos }))
      .catch((error: unknown) =>
        setState({
          status: 'error',
          message: error instanceof Error ? error.message : 'Не удалось загрузить данные',
        }),
      )
  }, [])

  if (state.status === 'loading') {
    return (
      <View style={styles.center}>
        <ActivityIndicator size="large" color="#0057B8" />
      </View>
    )
  }

  if (state.status === 'error') {
    return (
      <View style={styles.center}>
        <Text style={styles.error}>Не удалось загрузить фотографии</Text>
        <Text style={styles.message}>{state.message}</Text>
      </View>
    )
  }

  return (
    <View style={styles.center}>
      <Text style={styles.title}>Получено фотографий: {state.photos.length}</Text>
    </View>
  )
}
```

Обратите внимание: после проверки `state.status === 'success'` TypeScript сам понимает, что в поле `photos` лежит массив, и подсказывает поля объекта.

## Полный код

```tsx
import { StatusBar } from 'expo-status-bar'
import { useEffect, useState } from 'react'
import { ActivityIndicator, StyleSheet, Text, View } from 'react-native'

export type MarsPhoto = {
  id: number
  title: string
  url: string
}

type UiState =
  | { status: 'loading' }
  | { status: 'success'; photos: MarsPhoto[] }
  | { status: 'error'; message: string }

const API_URL = 'https://jsonplaceholder.typicode.com/photos?_limit=20'

async function fetchPhotos(): Promise<MarsPhoto[]> {
  const response = await fetch(API_URL)

  if (!response.ok) {
    throw new Error(`Сервер вернул код ${response.status}`)
  }

  return (await response.json()) as MarsPhoto[]
}

function MarsPhotosScreen() {
  const [state, setState] = useState<UiState>({ status: 'loading' })

  useEffect(() => {
    fetchPhotos()
      .then((photos) => setState({ status: 'success', photos }))
      .catch((error: unknown) =>
        setState({
          status: 'error',
          message: error instanceof Error ? error.message : 'Не удалось загрузить данные',
        }),
      )
  }, [])

  if (state.status === 'loading') {
    return (
      <View style={styles.center}>
        <ActivityIndicator size="large" color="#0057B8" />
      </View>
    )
  }

  if (state.status === 'error') {
    return (
      <View style={styles.center}>
        <Text style={styles.error}>Не удалось загрузить фотографии</Text>
        <Text style={styles.message}>{state.message}</Text>
      </View>
    )
  }

  return (
    <View style={styles.center}>
      <Text style={styles.title}>Получено фотографий: {state.photos.length}</Text>
    </View>
  )
}

export default function App() {
  return (
    <>
      <MarsPhotosScreen />
      <StatusBar style="auto" />
    </>
  )
}

const styles = StyleSheet.create({
  center: { flex: 1, alignItems: 'center', justifyContent: 'center', padding: 24 },
  title: { fontSize: 22, fontWeight: 'bold', textAlign: 'center' },
  error: { fontSize: 18, color: '#C62828', marginBottom: 8, textAlign: 'center' },
  message: { color: '#555555', textAlign: 'center' },
})
```

## Проверьте работу

1. Запустите проект командой `npx expo start` и откройте приложение на телефоне или в браузере.
2. Сначала появится индикатор загрузки, затем — надпись «Получено фотографий: 20».
3. Замените в адресе `_limit=20` на `_limit=5` — число изменится на 5.
4. Временно испортите адрес (например, добавьте лишнюю букву) — появится сообщение об ошибке.
5. Верните правильный адрес и перезагрузите приложение — данные снова загрузятся.

## Резюме

- REST — стиль веб-сервисов: ресурс доступен по адресу, действие задаётся HTTP-методом.
- `fetch` возвращает промис, поэтому результат получают через `await`.
- Ответ в формате JSON разбирают методом `response.json()` и описывают типом TypeScript.
- Всегда проверяйте `response.ok` — иначе ошибка сервера останется незамеченной.
- Состояние экрана удобно описывать объединением типов: загрузка, успех, ошибка.
- `useEffect` с пустым массивом зависимостей запускает загрузку один раз при открытии экрана.
