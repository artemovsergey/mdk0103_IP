### Что вы создадите

Приложение **Mars Photos** — сетка настоящих фотографий Марса, полученных с веб-сервиса, с индикатором загрузки и кнопкой «Повторить» при ошибке.

## Шаг 2. Адрес сервиса и формат ответа

В лекциях мы тренировались на учебном сервисе jsonplaceholder. Теперь загрузим настоящие снимки: учебный веб-сервис отдаёт список фотографий марсоходов. Адрес ресурса:

```tsx
const API_URL = 'https://android-kotlin-fun-mars-server.appspot.com/photos'
```

Ответ — JSON-массив объектов, у каждого только два поля:

- `id` — номер снимка (строка);
- `img_src` — адрес изображения в интернете.

Названия фотографий сервис не отдаёт, поэтому в сетке будут только изображения.

## Шаг 3. Тип данных и состояния экрана

Опишем тип, соответствующий ответу сервиса, и все три ситуации объединением типов — так же, как в лекции 20:

```tsx
type MarsPhoto = {
  id: string
  img_src: string
}

type UiState =
  | { status: 'loading' }
  | { status: 'success'; photos: MarsPhoto[] }
  | { status: 'error'; message: string }
```

Функция загрузки получает данные и переводит состояние из «загрузка» в «успех» или «ошибка»:

```tsx
async function fetchPhotos(): Promise<MarsPhoto[]> {
  const response = await fetch(API_URL)

  if (!response.ok) {
    throw new Error(`Сервер вернул код ${response.status}`)
  }

  return (await response.json()) as MarsPhoto[]
}
```

## Шаг 4. Сетка изображений

Изображение по адресу выводит встроенный компонент **`Image`**. Ему передают объект `source` с полем `uri` — компонент сам скачивает картинку, кэширует её и показывает по мере загрузки:

```tsx
<Image source={{ uri: photo.img_src }} style={styles.image} />
```

Стиль ячейки задаёт её форму и фон до появления картинки:

- `aspectRatio: 1` делает ячейку квадратной — фотографии не «прыгают» при загрузке;
- `backgroundColor` виден, пока изображение загружается;
- `borderRadius` скругляет углы.

`FlatList` строит сетку, если задать число колонок. На узком экране удобны две колонки, на широком — четыре, поэтому посчитаем их по ширине окна:

```tsx
function PhotoGrid({ photos }: { photos: MarsPhoto[] }) {
  const { width } = useWindowDimensions()
  const numColumns = width > 600 ? 4 : 2

  return (
    <FlatList
      key={numColumns}
      data={photos}
      numColumns={numColumns}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => <Image source={{ uri: item.img_src }} style={styles.image} />}
    />
  )
}
```

> `key={numColumns}` обязателен: `FlatList` не умеет менять число колонок на лету, поэтому при смене ширины окна список пересоздаётся.

`FlatList` ленивый: он создаёт ячейки только для видимой части экрана, поэтому изображения догружаются по мере прокрутки.

## Шаг 5. Полный код App.tsx

```tsx
import { StatusBar } from 'expo-status-bar'
import { useEffect, useState } from 'react'
import {
  ActivityIndicator,
  Button,
  FlatList,
  Image,
  StyleSheet,
  Text,
  useWindowDimensions,
  View,
} from 'react-native'

type MarsPhoto = {
  id: string
  img_src: string
}

type UiState =
  | { status: 'loading' }
  | { status: 'success'; photos: MarsPhoto[] }
  | { status: 'error'; message: string }

const API_URL = 'https://android-kotlin-fun-mars-server.appspot.com/photos'

async function fetchPhotos(): Promise<MarsPhoto[]> {
  const response = await fetch(API_URL)

  if (!response.ok) {
    throw new Error(`Сервер вернул код ${response.status}`)
  }

  return (await response.json()) as MarsPhoto[]
}

function PhotoGrid({ photos }: { photos: MarsPhoto[] }) {
  const { width } = useWindowDimensions()
  const numColumns = width > 600 ? 4 : 2

  return (
    <FlatList
      key={numColumns}
      data={photos}
      numColumns={numColumns}
      keyExtractor={(item) => item.id}
      contentContainerStyle={styles.grid}
      renderItem={({ item }) => <Image source={{ uri: item.img_src }} style={styles.image} />}
    />
  )
}

function MarsPhotosScreen() {
  const [state, setState] = useState<UiState>({ status: 'loading' })

  const loadPhotos = () => {
    setState({ status: 'loading' })

    fetchPhotos()
      .then((photos) => setState({ status: 'success', photos }))
      .catch((error: unknown) =>
        setState({
          status: 'error',
          message: error instanceof Error ? error.message : 'Не удалось загрузить данные',
        }),
      )
  }

  useEffect(() => {
    loadPhotos()
  }, [])

  if (state.status === 'loading') {
    return (
      <View style={styles.center}>
        <ActivityIndicator size="large" color="#0057B8" />
      </View>
    )
  }

  if (state.status === 'error') {
    return (
      <View style={styles.center}>
        <Text style={styles.error}>Не удалось загрузить фотографии</Text>
        <Text style={styles.message}>{state.message}</Text>
        <Button title="Повторить" onPress={loadPhotos} />
      </View>
    )
  }

  return (
    <View style={styles.screen}>
      <Text style={styles.title}>Mars Photos</Text>
      <PhotoGrid photos={state.photos} />
    </View>
  )
}

export default function App() {
  return (
    <>
      <MarsPhotosScreen />
      <StatusBar style="auto" />
    </>
  )
}

const styles = StyleSheet.create({
  screen: { flex: 1, backgroundColor: '#F5F5F5', paddingTop: 48 },
  center: { flex: 1, alignItems: 'center', justifyContent: 'center', padding: 24, gap: 12 },
  title: { fontSize: 24, fontWeight: 'bold', paddingHorizontal: 16 },
  error: { fontSize: 18, color: '#C62828', textAlign: 'center' },
  message: { color: '#555555', textAlign: 'center' },
  grid: { padding: 4, paddingBottom: 24 },
  image: {
    flex: 1,
    aspectRatio: 1,
    margin: 4,
    borderRadius: 8,
    backgroundColor: '#E0E0E0',
  },
})
```

## Резюме

- `Image` загружает изображение по `uri` и кэширует его — дополнительная библиотека не нужна.
- `FlatList` с `numColumns` строит сетку; при смене числа колонок список пересоздают через `key`.
- `aspectRatio` и `backgroundColor` делают сетку аккуратной даже во время загрузки картинок.
- Состояния загрузки, успеха и ошибки описывают объединением типов.
- Ошибку можно исправить повтором запроса — той же функцией загрузки по кнопке.
- `FlatList` ленивый: он создаёт только видимые ячейки, поэтому большие списки не тормозят.
