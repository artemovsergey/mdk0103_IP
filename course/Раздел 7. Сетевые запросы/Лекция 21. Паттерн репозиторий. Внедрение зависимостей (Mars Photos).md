# Лекция 21. Паттерн репозиторий. Внедрение зависимостей (Mars Photos)

В лекции 20 запрос данных был написан прямо в компоненте. Такой подход работает, но плохо масштабируется: когда источников данных становится несколько, а логика загрузки усложняется, код экранов превращается в смесь интерфейса и работы с сетью. Надёжнее разделить приложение на **слой представления** и **слой данных**.

В этой лекции вы отрефакторите приложение **Mars Photos**: выделите слой данных с помощью **паттерна репозиторий** и передадите зависимость извне — это и есть **внедрение зависимостей**.

### Пререквизиты

- Лекция 20 «Сетевые запросы (Mars Photos)».
- Умение выполнять запрос через `fetch` и обрабатывать состояния загрузки и ошибки.

### Что вы узнаете

- Зачем разделять приложение на слои.
- Что такое паттерн репозиторий и источник данных.
- Что такое внедрение зависимостей (dependency injection).
- Как передать зависимость через параметры и через React Context.

### Что вы создадите

Вы разделите Mars Photos на слой представления и слой данных, реализуете источник данных и репозиторий, а затем внедрите репозиторий в экран.

## Зачем нужны слои

Разделение на слои делает приложение:

- **масштабируемым** — новый источник данных добавляется, не затрагивая экраны;
- **тестируемым** — зависимость можно подменить фиктивной в тестах.

Минимальная схема — два слоя:

- **Слой представления (UI)** — компоненты, которые показывают данные и реагируют на действия пользователя.
- **Слой данных (Data)** — получение и сохранение данных, бизнес-логика.

Слой данных состоит из **репозиториев**, а те обращаются к **источникам данных**: сети, базе, файлам. Экран ничего не знает о том, откуда берутся данные, — он получает их через репозиторий. Такой принцип называют **разделением обязанностей**.

## Источник данных

Вынесем сетевой запрос в отдельный источник данных. Опишем его интерфейсом, а реализацию спрячем в классе:

```tsx
export type MarsPhoto = {
  id: number
  title: string
  url: string
}

export interface MarsPhotosRemoteDataSource {
  getPhotos(): Promise<MarsPhoto[]>
}

export class NetworkMarsPhotosDataSource implements MarsPhotosRemoteDataSource {
  async getPhotos(): Promise<MarsPhoto[]> {
    const response = await fetch('https://jsonplaceholder.typicode.com/photos?_limit=20')

    if (!response.ok) {
      throw new Error(`Сервер вернул код ${response.status}`)
    }

    return (await response.json()) as MarsPhoto[]
  }
}
```

Интерфейс `MarsPhotosRemoteDataSource` описывает, **что** умеет источник, а класс `NetworkMarsPhotosDataSource` — **как** он это делает. Позже такую же роль сможет выполнить источник, читающий данные из базы или из файла.

## Репозиторий

Репозиторий скрывает источник данных от остального приложения:

```tsx
export interface MarsPhotosRepository {
  getPhotos(): Promise<MarsPhoto[]>
}

export class DefaultMarsPhotosRepository implements MarsPhotosRepository {
  constructor(private remote: MarsPhotosRemoteDataSource) {}

  getPhotos(): Promise<MarsPhoto[]> {
    return this.remote.getPhotos()
  }
}
```

Обратите внимание на конструктор: репозиторий не создаёт источник данных сам, а **принимает его параметром**. Это и есть внедрение зависимостей — класс получает нужные объекты извне. Если завтра данные начнут кэшироваться в базе, изменится только реализация репозитория, а экраны останутся прежними. Так работает **инкапсуляция**.

## Внедрение зависимостей через параметры

Простейший способ передать зависимость — параметр функции или компонента. Создадим репозиторий один раз в корне приложения и передадим его в экран:

```tsx
function useMarsPhotos(repository: MarsPhotosRepository): UiState {
  const [state, setState] = useState<UiState>({ status: 'loading' })

  useEffect(() => {
    repository
      .getPhotos()
      .then((photos) => setState({ status: 'success', photos }))
      .catch((error: unknown) =>
        setState({
          status: 'error',
          message: error instanceof Error ? error.message : 'Не удалось загрузить данные',
        }),
      )
  }, [repository])

  return state
}

function MarsPhotosScreen({ repository }: { repository: MarsPhotosRepository }) {
  const state = useMarsPhotos(repository)

  if (state.status === 'loading') return <ActivityIndicator size="large" color="#0057B8" />
  if (state.status === 'error') return <Text style={styles.error}>Ошибка: {state.message}</Text>

  return <Text style={styles.title}>Получено фотографий: {state.photos.length}</Text>
}

export default function App() {
  const [repository] = useState(
    () => new DefaultMarsPhotosRepository(new NetworkMarsPhotosDataSource()),
  )

  return (
    <View style={styles.center}>
      <MarsPhotosScreen repository={repository} />
      <StatusBar style="auto" />
    </View>
  )
}
```

Хук `useMarsPhotos` получает репозиторий параметром и не знает, что внутри источник данных — сеть. Зависимости создаются в одном месте, а остальные части приложения получают их готовыми.

## Контейнер внедрения зависимостей через Context

Когда зависимость нужна многим экранам на разной глубине, передавать её через параметры становится неудобно. В React для этого есть **Context** — механизм, который раздаёт значение всем вложенным компонентам:

```tsx
import { createContext, useContext, useState } from 'react'

const RepositoryContext = createContext<MarsPhotosRepository | null>(null)

export function RepositoryProvider({ children }: { children: React.ReactNode }) {
  const [repository] = useState(
    () => new DefaultMarsPhotosRepository(new NetworkMarsPhotosDataSource()),
  )

  return <RepositoryContext.Provider value={repository}>{children}</RepositoryContext.Provider>
}

export function useRepository(): MarsPhotosRepository {
  const repository = useContext(RepositoryContext)

  if (!repository) {
    throw new Error('RepositoryProvider отсутствует')
  }

  return repository
}
```

`RepositoryProvider` создаёт зависимости в одном месте и раздаёт их всем, кому они нужны, — такой компонент называют **контейнером внедрения зависимостей**. Хук `useRepository` достаёт репозиторий из контекста и заодно проверяет, что провайдер подключён.

Дальше хук `useMarsPhotos` просто берёт репозиторий из контекста — `const repository = useRepository()` — и весь остальной код экрана не меняется. Полный листинг со всеми правками — ниже.

## Полный код

```tsx
import { StatusBar } from 'expo-status-bar'
import { createContext, useContext, useEffect, useState } from 'react'
import { ActivityIndicator, StyleSheet, Text, View } from 'react-native'

type MarsPhoto = {
  id: number
  title: string
  url: string
}

interface MarsPhotosRemoteDataSource {
  getPhotos(): Promise<MarsPhoto[]>
}

class NetworkMarsPhotosDataSource implements MarsPhotosRemoteDataSource {
  async getPhotos(): Promise<MarsPhoto[]> {
    const response = await fetch('https://jsonplaceholder.typicode.com/photos?_limit=20')

    if (!response.ok) {
      throw new Error(`Сервер вернул код ${response.status}`)
    }

    return (await response.json()) as MarsPhoto[]
  }
}

interface MarsPhotosRepository {
  getPhotos(): Promise<MarsPhoto[]>
}

class DefaultMarsPhotosRepository implements MarsPhotosRepository {
  constructor(private remote: MarsPhotosRemoteDataSource) {}

  getPhotos(): Promise<MarsPhoto[]> {
    return this.remote.getPhotos()
  }
}

const RepositoryContext = createContext<MarsPhotosRepository | null>(null)

function RepositoryProvider({ children }: { children: React.ReactNode }) {
  const [repository] = useState(
    () => new DefaultMarsPhotosRepository(new NetworkMarsPhotosDataSource()),
  )

  return <RepositoryContext.Provider value={repository}>{children}</RepositoryContext.Provider>
}

function useRepository(): MarsPhotosRepository {
  const repository = useContext(RepositoryContext)

  if (!repository) {
    throw new Error('RepositoryProvider отсутствует')
  }

  return repository
}

type UiState =
  | { status: 'loading' }
  | { status: 'success'; photos: MarsPhoto[] }
  | { status: 'error'; message: string }

function useMarsPhotos(): UiState {
  const repository = useRepository()
  const [state, setState] = useState<UiState>({ status: 'loading' })

  useEffect(() => {
    repository
      .getPhotos()
      .then((photos) => setState({ status: 'success', photos }))
      .catch((error: unknown) =>
        setState({
          status: 'error',
          message: error instanceof Error ? error.message : 'Не удалось загрузить данные',
        }),
      )
  }, [repository])

  return state
}

function MarsPhotosScreen() {
  const state = useMarsPhotos()

  if (state.status === 'loading') {
    return (
      <View style={styles.center}>
        <ActivityIndicator size="large" color="#0057B8" />
      </View>
    )
  }

  if (state.status === 'error') {
    return (
      <View style={styles.center}>
        <Text style={styles.error}>Ошибка: {state.message}</Text>
      </View>
    )
  }

  return (
    <View style={styles.center}>
      <Text style={styles.title}>Получено фотографий: {state.photos.length}</Text>
    </View>
  )
}

export default function App() {
  return (
    <RepositoryProvider>
      <MarsPhotosScreen />
      <StatusBar style="auto" />
    </RepositoryProvider>
  )
}

const styles = StyleSheet.create({
  center: { flex: 1, alignItems: 'center', justifyContent: 'center', padding: 24 },
  title: { fontSize: 22, fontWeight: 'bold', textAlign: 'center' },
  error: { fontSize: 18, color: '#C62828', textAlign: 'center' },
})
```

## Резюме

- Слой данных отделён от слоя представления — каждый занимается своим делом.
- **Репозиторий** скрывает источники данных от остального приложения.
- **Внедрение зависимостей** — передача зависимостей извне; простейший способ — параметры.
- **Context** работает как контейнер зависимостей, когда их нужно раздать многим компонентам.
- Компоненты получают данные через хук и не выполняют запросы сами.
