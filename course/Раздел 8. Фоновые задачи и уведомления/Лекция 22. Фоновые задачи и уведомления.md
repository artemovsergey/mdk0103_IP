# Лекция 22. Фоновые задачи и уведомления

Пока приложение открыто, оно полностью управляет происходящим: реагирует на нажатия, обновляет экран, загружает данные. Но многие задачи должны выполняться иначе — напомнить пользователю полить растение, сообщить о новом сообщении, обновить данные к утру. Для этого приложение либо составляет сообщение заранее, либо просит систему выполнить код в удобный момент, когда приложение закрыто. Существуют два механизма: **локальные уведомления** и **фоновые задачи**. В этом занятии вы познакомитесь с обоими и научитесь планировать их в Expo.

### Что вы узнаете

- Чем локальное уведомление отличается от фоновой задачи.
- Как запросить разрешение на уведомления.
- Как планировать и отменять локальные уведомления через `expo-notifications`.
- Как настроить каналы уведомлений на Android.
- Как реагировать на нажатие по уведомлению.
- Как устроены фоновые задачи в `expo-background-task` и `expo-task-manager`.

### Что вам понадобится

- Настроенное окружение Expo (см. «Настройка окружения Expo»).
- Телефон с приложением Expo Go.
- Умение работать с хуками `useState` и `useEffect` (лекция 15).

## Зачем приложению уведомления и фоновые задачи

Приложение не может реагировать на события, если оно закрыто, но пользователю всё равно нужны напоминания:

- напомнить полить растение или принять лекарство;
- сообщить о новом сообщении или письме;
- обновить расписание или данные к утру;
- синхронизировать заметки с сервером.

Для таких сценариев и существуют два инструмента.

**Локальное уведомление** — это сообщение, которое приложение составляет заранее и передаёт системе. Система показывает его в назначенный момент, даже если приложение закрыто. Приложение не выполняется в этот момент — оно лишь заранее «попросило» показать сообщение.

**Фоновая задача** — это код, который система запускает сама, в удобный для неё момент: например, чтобы скачать обновления или отправить накопленные данные.

| Механизм | Когда срабатывает | Что делает | Expo Go |
|---|---|---|---|
| Локальное уведомление | В назначенный момент | Показывает сообщение | Поддерживается |
| Фоновая задача | Когда решит система | Выполняет код приложения | Не поддерживается |

## Локальные уведомления: expo-notifications

За локальные уведомления в Expo отвечает пакет **`expo-notifications`**. Установите его в проект:

```bash
npx expo install expo-notifications
```

Пакет умеет и то, и другое: показывать локальные уведомления и принимать уведомления с сервера (удалённые, push). В этом курсе мы используем только локальные: они работают в Expo Go, а для удалённых нужна дополнительная настройка сервера.

## Разрешения

Прежде чем показать первое уведомление, приложение должно получить разрешение пользователя. Проверка и запрос выполняются двумя методами:

```ts
const settings = await Notifications.getPermissionsAsync()

if (!settings.granted) {
  await Notifications.requestPermissionsAsync()
}
```

- `getPermissionsAsync` — проверяет текущий статус, ничего не показывая.
- `requestPermissionsAsync` — открывает системный диалог с вопросом «Разрешить уведомления?».
- `granted` — `true`, если разрешение выдано.

Запрашивать разрешение лучше один раз при запуске приложения, а не перед каждым уведомлением.

## Обработчик уведомлений

По умолчанию система может не показать уведомление, пока приложение открыто на экране. Поведение задаёт обработчик `setNotificationHandler`. Его вызывают один раз в начале файла, вне компонента:

```ts
import * as Notifications from 'expo-notifications'

Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldShowBanner: true,
    shouldShowList: true,
    shouldPlaySound: true,
    shouldSetBadge: false,
  }),
})
```

- `shouldShowBanner` — показать всплывающую плашку поверх экрана.
- `shouldShowList` — добавить запись в центр уведомлений.
- `shouldPlaySound` — проиграть звук.
- `shouldSetBadge` — изменить значок на иконке приложения.

Функция-обработчик должна вернуть результат быстро — не дольше трёх секунд.

## Планирование уведомления

Уведомление планируют методом `scheduleNotificationAsync`. Ему передают два объекта: `content` (что показать) и `trigger` (когда показать):

```ts
const id = await Notifications.scheduleNotificationAsync({
  content: {
    title: 'Пора полить растение',
    body: 'Не забудьте полить фикус',
    data: { plantId: '1' },
  },
  trigger: {
    type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL,
    seconds: 60,
    repeats: true,
  },
})
```

- `title` и `body` — заголовок и текст уведомления.
- `data` — любые дополнительные данные; их получит обработчик нажатия.
- `type` — обязательное поле: оно сообщает системе тип триггера.
- `seconds: 60` — интервал в секундах; `repeats: true` — повторять бесконечно.
- Метод возвращает **идентификатор** уведомления — по нему его можно отменить.

Основные типы триггеров:

| Тип | Когда срабатывает |
|---|---|
| `TIME_INTERVAL` | Через заданное число секунд (`seconds`) |
| `DATE` | В конкретную дату и время (`date`) |
| `DAILY` | Каждый день в указанный час и минуту (`hour`, `minute`) |

Уведомление на конкретную дату:

```ts
const date = new Date(Date.now() + 60 * 60 * 1000)

await Notifications.scheduleNotificationAsync({
  content: { title: 'Через час' },
  trigger: { type: Notifications.SchedulableTriggerInputTypes.DATE, date },
})
```

Ежедневное напоминание в 9:00 — один раз запланировали, дальше система повторяет сама:

```ts
trigger: {
  type: Notifications.SchedulableTriggerInputTypes.DAILY,
  hour: 9,
  minute: 0,
}
```

## Отмена уведомлений

Отменить конкретное уведомление можно по идентификатору, а все сразу — одним методом:

```ts
await Notifications.cancelScheduledNotificationAsync(id)
await Notifications.cancelAllScheduledNotificationsAsync()
```

Посмотреть, что уже запланировано, помогает `getAllScheduledNotificationsAsync` — удобно при отладке.

## Каналы уведомлений на Android

На Android уведомления приходят по **каналам**. Канал создают один раз при запуске, до планирования уведомлений:

```ts
import { Platform } from 'react-native'

if (Platform.OS === 'android') {
  await Notifications.setNotificationChannelAsync('reminders', {
    name: 'Напоминания',
    importance: Notifications.AndroidImportance.MAX,
  })
}
```

- `name` — название канала, которое увидит пользователь в настройках.
- `importance` — важность: с `MAX` уведомление показывается плашкой и привлекает внимание.
- Идентификатор канала (`'reminders'`) указывают в поле `channelId` внутри триггера.

## Реакция на нажатие по уведомлению

Когда пользователь нажимает на уведомление, приложение может выполнить действие. Нажатие обрабатывает слушатель `addNotificationResponseReceivedListener`:

```ts
useEffect(() => {
  const subscription = Notifications.addNotificationResponseReceivedListener((response) => {
    const plantId = response.notification.request.content.data.plantId
    console.log('Нажали по уведомлению растения', plantId)
  })

  return () => subscription.remove()
}, [])
```

- Данные `data`, переданные при планировании, доступны в `content.data`.
- Слушатель возвращает подписку с методом `remove` — её нужно снимать при размонтировании компонента.
- Другой вариант — `useLastNotificationResponse`, если нажатие могло запустить приложение заново.

## Фоновые задачи: expo-background-task и expo-task-manager

Если нужно не показать сообщение, а **выполнить код** без открытого приложения — например, раз в сутки проверять обновления — используют фоновую задачу. Для этого нужны два пакета:

```bash
npx expo install expo-background-task expo-task-manager
```

Задача описывается через `TaskManager.defineTask` в начале файла, вне компонента: задача должна существовать, даже когда экран закрыт.

```tsx
import AsyncStorage from '@react-native-async-storage/async-storage'
import * as BackgroundTask from 'expo-background-task'
import * as TaskManager from 'expo-task-manager'

const TASK_NAME = 'sync-example'

TaskManager.defineTask(TASK_NAME, async () => {
  try {
    const now = new Date().toISOString()
    const previous = await AsyncStorage.getItem('last-sync')

    console.log('Фоновая задача запустилась:', now, 'предыдущий запуск:', previous)
    await AsyncStorage.setItem('last-sync', now)

    return BackgroundTask.BackgroundTaskResult.Success
  } catch (error) {
    console.error('Ошибка фоновой задачи:', error)
    return BackgroundTask.BackgroundTaskResult.Failed
  }
})

async function registerSyncTask() {
  await BackgroundTask.registerTaskAsync(TASK_NAME, {
    minimumInterval: 60,
  })
}
```

Разберём ключевые моменты:

- `TASK_NAME` — строка-имя задачи; она связывает `defineTask` и `registerTaskAsync`.
- Функция задачи обязана вернуть `Success` или `Failed` — так система понимает, выполнилась ли работа.
- `minimumInterval` указывается **в минутах**, минимум — 15 минут. Значение 60 означает «примерно раз в час».
- Точное время запуска определяет система: она учитывает заряд батареи, наличие сети и активность пользователя, поэтому задача может выполниться позже указанного интервала.
- Отменить задачу можно методом `BackgroundTask.unregisterTaskAsync(TASK_NAME)`, а проверить доступность — `BackgroundTask.getStatusAsync()`.

> **Важно.** Фоновые задачи не работают в Expo Go: система запускает их только у собранного приложения. Нужен development build — настоящую сборку выполним в практической работе 30. Поэтому прямо сейчас, в практических работах 27 и 28, мы используем локальные уведомления: они полностью работают в Expo Go и так же срабатывают, когда приложение закрыто.

## Что выбрать

- **Нужно напомнить пользователю** — локальное уведомление: оно придёт точно в назначенный момент и работает в Expo Go.
- **Нужно выполнить код в фоне** — фоновая задача: время запуска определяет система, а для проверки потребуется development build.

## Резюме

- Уведомление показывает сообщение, фоновая задача выполняет код без открытого приложения.
- Разрешение проверяют через `getPermissionsAsync`, а запрашивают через `requestPermissionsAsync`.
- `setNotificationHandler` задаёт поведение уведомлений, когда приложение открыто.
- `scheduleNotificationAsync` планирует уведомление и возвращает идентификатор для отмены.
- Триггеры бывают трёх основных видов: `TIME_INTERVAL`, `DATE`, `DAILY`; поле `type` обязательно.
- На Android уведомления доставляются по каналам: канал создаёт `setNotificationChannelAsync`.
- Нажатие обрабатывает `addNotificationResponseReceivedListener`.
- Фоновые задачи описывают через `TaskManager.defineTask` и регистрируют через `registerTaskAsync`; в Expo Go они не работают — нужен development build.
